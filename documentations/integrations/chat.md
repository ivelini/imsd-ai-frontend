# Интеграция: публичный чат (ИИ-ассистент)

Проверено 13.11.2026 (варианты `options` — 16.11.2026) по
`../backend/documentations/api-maps/public-chat.md`, `public-chat-frontend.md` и Scramble-экспорту
`../backend/documentations/scramble/public-api.json`.
Источник истины — экспорт/код бэка.

Запросы идут через `apiBase()`: сервер — `BACKEND_URL`, браузер — `/api` через
`rewrites()` в `next.config.ts`.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/chat` | Вопрос `{message, city?}` 1–2000 символов → 202 `{session_token, message_id, status}`; без `X-Session-Token` создаёт диалог |
| GET | `/api/chat/messages` | Реплики `{data: [{id, role, content, created_at, options?}]}`; заголовок `X-Session-Token` обязателен; без `after_id` — последние до 200 реплик |

## Варианты ответа (`options`)

У реплики ассистента может быть `options: [{label, text?, url?}]` — кнопки под текстом.
У варианта либо `text` — реплика при клике, либо `url` — относительный путь каталога
с параметрами и городом. Бэк строит их по данным инструментов (`search_vehicle`,
`vehicle_tires`, `vehicle_wheels`, `search_tires`); ключа нет, когда выбора не было.

- Показываются только у **последней** реплики ленты (`lastOptions`).
- `text`: клик отправляет его в POST `/api/chat` как обычное сообщение; пока отправка идёт,
  кнопки `disabled`; после успеха последняя реплика — вопрос пользователя, варианты исчезают.
- `url`: клик — переход в той же вкладке без перезагрузки (`router.push`); если адрес совпадает
  с текущим — `router.refresh()` (`isCurrentLocation`). POST не вызывается; окно чата остаётся
  открытым, страница каталога перезапрашивается на сервере. Средний/ctrl-клик работает нативно.
- После клика варианты этой реплики скрываются (`dismissedMessageId`), дальше действует
  правило «только последняя реплика».
- Введённый в поле текст клик не трогает; `options` — данные, не HTML.

## Город витрины

POST принимает `city` (слаг, приоритет у `city_id`); город сохраняется в диалоге и определяет
цены, наличие и сроки доставки в ответах. Фронт шлёт `city` с каждым сообщением — бэк обновляет
город сессии на каждом POST (`StartPublicChatTurn::rememberCity`), поэтому смена города на сайте
продолжает текущий диалог, а следующий ответ считается по новому городу. Значение — город,
который посетитель видит на сайте: `useCity().citySlug` (выбранный `cityValue` или дефолт geo;
`effectiveCitySlug`). Пока geo не загружена, город пуст и в тело не попадает — бэк берёт город
магазина по умолчанию. Неизвестный слаг бэк заменяет дефолтным городом (не 422).

Токен — uuid, только заголовком `X-Session-Token`. Роли наружу — `user` и `assistant`;
служебные `system` не отдаются. `created_at` — ISO с таймзоной (бывает `null`).

## Ошибки (различение по статусу и `code`, не по тексту)

| Статус | Что делает фронт |
|---|---|
| 400 `ai.off_topic` | Текст бэка плашкой в ленте; реплика не записана, введённый текст остаётся |
| 404 | Токен протух: токен стирается, остаётся приветствие; следующий POST создаёт новый диалог |
| 422 | Технические ключи `validation.*` на экран не пускаются — общий текст |
| 429 | Текст бэка (лимит/бюджет), поллинг останавливается |
| 5xx / сеть | «Сервис временно недоступен» + «Повторить» (возобновляет опрос, POST не повторяется) |

## Фронт

- `src/shared/api/chat.ts` — DTO и запросы (`sendChatMessage({message, token?, city?})`);
  `src/shared/api/http.ts` — `readJson`, `ApiError`, `toErrorResponse` (общие с booking).
- `src/shared/lib/cityUrl.ts` — `effectiveCitySlug`; `useCity` (`shared/layout/api`) отдаёт
  `citySlug` — его и шлёт `ChatWindow`.
- `src/features/chat/lib/` — чистые правила: `errors.ts` (статус+`code` → состояние),
  `time.ts` (ISO → «ЧЧ:ММ»), `polling.ts` (опрос до 60 с, продление повтором),
  `options.ts` (варианты только у последней реплики ассистента),
  `session.ts` (токен в localStorage `chat_session_token`).
- `src/features/chat/api/` — `useChatMessages` (React Query, поллинг полным списком раз в 1,5 с,
  пока последняя реплика — вопрос пользователя и не истекло 60 с), `useSendChatMessage`.
- `src/features/chat/components/` — `ChatWidget` (панель: до 639 px круглая кнопка, с 640 px
  плашка) и `ChatWindow` (лента, приветствие, ошибки, ввод до 5 строк, ресайз за левый
  верхний угол). Смонтирован в `src/app/layout.tsx` на всех страницах.
- Стили — блок `.chat-*` в конце `src/app/style.css` (13.11.2026), перенос макета `.template/chat/`.

## Ограничения контракта

- Стрима нет (SSE/WebSocket) — только поллинг.
- Лимиты: 20 сообщений в сутки на диалог, 200 на канал, 10 POST/мин и 60 GET/мин с IP;
  диалог хранится 30 дней.
- Ответ с внутренней лексикой бэк заменяет на «Не могу ответить на этот вопрос» — показываем как есть.
- **Исправлено 13.11.2026 (ТЗ `tz/chat-empty-assistant-backend.md`):** витрина больше не отдаёт
  реплики `assistant` с пустым `content` — шаги вызова инструментов скрыты, поллинг видит только
  настоящий ответ. Пустых пузырей и «зависшего» ожидания после исправления нет.
