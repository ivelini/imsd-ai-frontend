# Эксплуатация

## Деплой

Прод — сайт `aalyans74.ru` на сервере с ISPmanager (тот же сервер, что у бэка: `api.aalyans74.ru`).
Тип сайта в панели — **Node.js**: nginx отдаёт существующие файлы из каталога сайта, всё
остальное проксирует на unix-сокет `/var/www/aalyans74_ru/data/nodejs/0.sock`, который слушает
наше приложение. Приложение запускает панель через pm2 (`npm start`, cwd — каталог сайта),
каталог сайта — ссылка на выпущенный релиз.

Серверная часть выкладки — только rsync, `npm ci` и перезапуск процесса; сборка Next идёт на
раннере GitHub. Node на сервере — панельные `/usr/lib/ispnodejs/bin/node` (24.12) и nvm
(`/var/www/aalyans74_ru/data/.nvm/versions/node/v24.21.0`, им pm2 запускает приложение).

Два workflow в `.github/workflows/`:

| Файл | Когда запускается | Что делает |
|---|---|---|
| `ci.yml` | Вызывается выкладкой (`workflow_call`); сам не запускается | ESLint, `tsc --noEmit`, Vitest |
| `deploy.yml` | Пуш в `master`; вручную — Actions → «Выкладка на прод» → Run workflow | Прогоняет `ci.yml`, собирает приложение на раннере, разворачивает новый релиз, переключает на него ссылку каталога сайта, перезапускает приложение и проверяет ответ. Пуши других веток и pull request ничего не запускают |

У обеих задач задан `timeout-minutes` (по 20): умолчание — 360 минут, и зависший прогон держал
бы очередь выкладок часами.

### Раскладка на сервере

```
BASE_PATH = /var/www/aalyans74_ru/data/www
├── releases_front_aalyans74/<дата-время>/   код релиза + .next (сборка раннера) + node_modules (npm ci на сервере)
├── build/.env.frontend.prod                 .env прода — вне релиза, копией в релиз при выкладке
└── aalyans74.ru -> releases_front_aalyans74/<последний выпущенный>   каталог сайта: его обслуживает ISPmanager
```

Каталог сайта — ссылка на последний выпущенный релиз: её и обслуживает ISPmanager, менять путь в
панели не нужно. Выкладка собирает релиз рядом, и только когда всё готово, переключает ссылку
одной атомарной операцией. Старые релизы остаются на диске (`KEEP_RELEASES`, по умолчанию 3) —
это и есть откат.

Релиз содержит: код, `.next` (собран на раннере), `node_modules` (`npm ci --omit=dev` на сервере),
`.env` (копия из `build/`). Серверные запросы к бэку идут по `BACKEND_URL` из `.env`; в сборке
адрес бэка запекается в `rewrites()` — правило «менять оба места сразу» в шапке `deploy.yml`.

Перезапуск — командой `pm2 restart aalyans74.ru` с `PM2_HOME=/var/www/aalyans74_ru/data/.pm2`.
Пауза при перезапуске — 1–2 секунды: сайт на это время отдаёт 502 от nginx (окна «сайт без кода»,
как у бэка с PHP, у Node-приложения нет — процесс один).

### Настройки выкладки

В блоке `env` задачи `deploy` (`deploy.yml`, «НАСТРОЙКИ ВЫКЛАДКИ») — правятся прямо в файле:

| Имя | Значение |
|---|---|
| `PROD_HOST` | адрес прод-сервера |
| `PROD_USER` | пользователь SSH (владелец каталога выкладки) |
| `PROD_SSH_PORT` | порт SSH |
| `BASE_PATH` | каталог выкладки |
| `DIR_NAME` | каталог сайта (он же адрес сайта) — выкладка переключает его ссылкой на релиз |
| `RELEASES` | каталог релизов внутри `BASE_PATH` |
| `APP_NAME` | имя приложения в pm2 (заводит панель при переводе сайта на Node.js) |
| `PM2_HOME`, `PM2_BIN` | домашний каталог pm2 пользователя и панельный бинарь pm2 |
| `NODE_BIN_DIR` | панельные node и npm — в SSH-сессии их нет в `PATH` |
| `SOCKET_PATH` | сокет, на который смотрит nginx |
| `BACKEND_URL` | адрес бэка для сборки; тот же адрес — в `build/.env.frontend.prod` |
| `KEEP_RELEASES` | сколько релизов хранить |

Единственное, что живёт в GitHub, — приватный ключ: секрет `PROD_SSH_KEY` (Settings → Secrets
and variables → Actions → Secrets), тот же ключ, что у бэка. В репозиторий ключ не кладётся:
он открывает прод.

⚠️ **Репозиторий публичный.** Всё, что вписано в блок `env`, видят все: адрес сервера,
пользователь SSH и путь выкладки. Ключ в секрете это не раскрывает, но саму инфраструктуру
показывает (у бэка такие же значения уже опубликованы).

### Подготовка сервера (один раз)

1. Секрет `PROD_SSH_KEY` в репозитории `ivelini/imsd-ai-frontend` — содержимое ключа
   `~/.ssh/id_aalyans74_ru` (как у бэка).
2. `BASE_PATH/build/.env.frontend.prod` — минимум `BACKEND_URL=https://api.aalyans74.ru`.
   Без файла выкладка падает с понятным сообщением.
3. Убрать заглушку панели (каталог, который создал ISPmanager при переводе сайта на Node.js):

   ```bash
   cd /var/www/aalyans74_ru/data/www
   mv aalyans74.ru aalyans74.ru.placeholder-06.10.2026   # не удалять: пусть лежит рядом
   ```

   Ссылку на релиз создаст первая выкладка. Если каталог сайта остался настоящим каталогом,
   выкладка останавливается до подмены — сайт не трогается.
4. Первый прогон выкладки (Actions → «Выкладка на прод» → Run workflow).

### Откат

Переключить ссылку на предыдущий релиз и перезапустить приложение:

```bash
cd /var/www/aalyans74_ru/data/www
ln -sfn releases_front_aalyans74/<предыдущий> aalyans74.ru.new && mv -T aalyans74.ru.new aalyans74.ru
PM2_HOME=/var/www/aalyans74_ru/data/.pm2 /usr/lib/ispnodejs/bin/pm2 restart aalyans74.ru
```

### Диагностика

```bash
PM2_HOME=/var/www/aalyans74_ru/data/.pm2 /usr/lib/ispnodejs/bin/pm2 status
PM2_HOME=/var/www/aalyans74_ru/data/.pm2 /usr/lib/ispnodejs/bin/pm2 logs aalyans74.ru --lines 50
curl -sS --unix-socket /var/www/aalyans74_ru/data/nodejs/0.sock -H 'Host: aalyans74.ru' http://localhost/ | head
```

Признаки на странице-заглушке панели («Website aalyans74.ru is ready») — приложение не поднялось
или каталог сайта не ссылка. Ответ 502 от nginx — процесс pm2 не слушает сокет, смотреть логи.
