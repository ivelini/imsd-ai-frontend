# 0011. Адреса модели и карточки дисков: модельный сегмент в URL

- **Статус:** Accepted
- **Дата:** 2026-11-10
- **Связанные ADR:** 0007 (заменён в части дисков), 0003 (пагинация размеров модели)

## Контекст

У дисков появилась карточка модели (`GET /api/catalog/wheel-models/{brand}/{model}`) — паритет с шинами. Прежний адрес карточки диска `/wheels/{brand}/{size}` (ADR 0007) не оставлял места странице модели: обе формы занимали один уровень пути. Каталог на момент решения не проиндексирован — адреса можно менять без редиректов.

## Решение

Адреса дисков — зеркало шин:

- модель — `/wheels/{brand}/{model}`;
- карточка — `/wheels/{brand}/{model}/{size}`.

Модельный сегмент — декоративный: API карточки диска модели не принимает (`/api/catalog/wheels/{brand}/{size}`), фронт передаёт в запрос только бренд и позицию. У диска без модели сегмент — `-`.

## Почему (альтернативы)

- `/wheels/{brand}/model/{model}` — не трогал карточки, но вводил служебное слово в адрес, которого нет у шин.
- Литеральный `/wheel-models/{brand}/{model}` — зеркалил API, но выбивался из раздела `/wheels` и оставлял две несвязанные схемы адресов.
- Оставить `/wheels/{brand}/{size}` и различать модель/карточку по ответу API — два запроса и неоднозначный 404.

Цена: старые адреса карточек дают 404; редиректы не заводим — каталог не проиндексирован, все внутренние ссылки строит `productUrl`.

## Последствия

Схема адресов шин и дисков одна; крошки и ссылки листингов строят общие помощники `productUrl`/`modelUrl`/`modelCrumb`. Модельный сегмент карточки ни с чем не сверяется — адрес с неверной моделью отдаст товар; канонизацию адреса вводим, если понадобится. Пересмотрим при появлении внешних ссылок на старые адреса — тогда редиректы.
