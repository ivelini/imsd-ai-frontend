# 0008. Бейдж — общий объект фронта: страница выводит плашки, если в data пришёл badges

- **Статус:** Accepted
- **Дата:** 2026-10-23
- **Связанные ADR:** 0001 (баррел `shared/api/data.ts`), 0007 (адреса карточек товара)

## Контекст
Бэк ввёл универсальные баджи (свой ADR `common/0045`): цветной ярлык с текстом, иконкой
и ссылкой, привязанный к товару, модели, бренду или статье; стек наследуется по цепочке
«товар → модель → бренд». Плашка бейджа на витрине уже спроектирована — это полоса
преимуществ в шапке (`.benefits` > `.benefit`: иконка, цвет, текст, ссылка); сейчас она
наполнена моком. Бейджи нужны не только в карточке товара, а на любой странице, а
решение «где показывать» принимает бэк: он либо кладёт поле в ответ, либо нет.

## Решение
Бейдж на фронте — один общий объект, а разметка в каждой зоне отдельно:

- `shared/types/badge.ts` — форма элемента стека (текст, цвет-пресет, иконка, ссылка);
- `shared/ui/badgeView.ts` — чистая функция представления (класс плашки, иконка, ссылка);
  вынесена отдельно, потому что рендер без DOM не проверить в тестах;
- `shared/ui/Badge.tsx` — компонент плашки и полосы: без знания о товаре и каталоге.

Правило одно: **пришёл в `data` объект `badges` — страница выводит плашки**. Страница
сама решает, где в разметке их поставить (карточка товара и главная — полосой шаблона
`.benefits` перед крошками/контентом). Пустой стек — ничего не выводится.

Разметка плашки — из шаблона: `benefit benefit--{color}` + иконка + текст. Пресеты
`BadgeColor` бэка (`red|gold|green`) совпадают с классами шаблона один в один — словарей
отображения на фронте нет. `icon_key` выбирает иконку из набора шаблона, неизвестный ключ —
иконка по цвету. Полоса-преимущества в шапке (мок `attention_blocks`) убрана: бейджи
приходят с данными страницы, а не рисуются шапкой.

## Почему (альтернативы)
Свой компонент в каждой зоне отклонён: разметка и правила разъезжатся, а бейдж — один
и тот же объект. Свой дизайн плашки (в макете её для товара нет) отклонён: пресеты бэка
уже спроектированы под шаблон, второй дизайн разошёлся бы с админкой. Рендер на бэке
(HTML готовой строкой) отклонён: теряются ссылка и иконка, а бэк отдаёт данные, а не
разметку. Логику в компоненте оставили в чистой функции: в проекте нет RTL, а логику
нужно тестировать. Держать полосу в шапке на моке отклонён: мок — это дубль контракта
бэка, который всё равно придётся переводить.

## Последствия
Логика бейджа живёт в `shared/`, зоны подключают её без дублирования. Пока бэк отдаёт
`badges` только в карточке товара, на остальных страницах полосы нет — чтобы промо-полоса
осталась на главной, каталоге и корзине, бэк должен положить `badges` в их ответы
(см. ТЗ `documentations/tz/badges-zones-backend.md`; главная: поле называется `badges`,
а не `attention_blocks`). Если бэк заведёт новый цвет-пресет, нужен новый класс плашки на
фронте; новый ключ иконки — новая иконка в наборе шаблона.
