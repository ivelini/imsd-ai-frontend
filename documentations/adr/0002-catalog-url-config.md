# 0002. Конфиг-грамматика URL каталога

- **Статус:** Accepted
- **Дата:** 2026-08-07 (обн. 21.08.2026 — префиксные размеры w/p, 404 на мусор)
- **Связанные ADR:** —

## Контекст
URL-грамматика каталога (сегменты + query) в `shared/lib/parseParams.ts` реализована двумя парами функций — шины и диски: одинаковый каркас (цикл по сегментам, сборка path+query, общие query-поля price/country/delivery/page), разные порядок сегментов и query-ключи (pcd/et/hub_bore/wheel_type у дисков, tire_type у шин). Семантика тонкая: сезон — только первый нечисловой сегмент, бренд — первый не-сезонный.

## Решение
Грамматика описывается конфигом `CatalogUrlConfig` (segmentParsers, queryParsers, segmentOrder, extraQueryFields) + обобщёнными `parseUrl`/`buildUrl`. `TIRES_CONFIG`/`WHEELS_CONFIG` — данные; старые функции остались обёртками, потребители не менялись. Новая категория (мотошины и т.п.) = новый конфиг без копирования каркаса.

С 21.08.2026 размеры шин — именованные префиксные сегменты `w185`/`p60`/`r15` (каноничный порядок `season/brand/w/p/r`), а не позиционная пара чисел: профиль без ширины и любая комбинация размеров выразимы без потерь при round-trip. Сегмент, не распознанный ни одним парсером (голое число, дубль бренда/сезона, строка вне каноничного порядка), — `InvalidCatalogUrlError` → страница отдаёт 404. Контракт справочника фильтра приведён к тому же виду: бэк отдаёт value с префиксами (`w185`, `p60`), 1:1 с сегментами URL; адаптер нормализует голые числа в переходный период.

## Почему (альтернативы)
По Rule of Three (обобщать на третьей копии) допустимо оставить две пары функций — обобщили на второй, потому что каркас идентичен на ~70% и третья категория почти наверняка появится. Цена выбора: уровень абстракции (конфиг) при двух реализациях; порядок query-параметров в URL может отличаться от прежнего (на парсинг не влияет).

Для префиксов рассматривали: плейсхолдер «-» в позиционной грамматике (оставляет хрупкость позиций и некрасивые URL) и перенос всех размеров в query (теряет SEO-сегменты в пути) — отвергнуты. Цена префиксов: старые URL с голыми числами в пути не распознаются (404); обратная совместимость сознательно не нужна — проект в разработке.

## Последствия
Одна пара функций вместо двух; семантики (сезон/бренд, fallback-query) зафиксированы в одном месте. Префиксная грамматика: URL каталога — каноничный контракт, генерируемый `buildCatalogUrl`; мусор на входе — 404, а не тихая порча фильтра. У дисков ширина осталась числом (`6.5`), но строгий `parseUrl` применяется и к ним: нераспознанный сегмент — тоже 404. Пересмотрим: если размеры станут мультивыбором (бэк принимает `width[]` массивами) — сегменты не выражают массивы, формат переедет в query; тогда грамматика упростится, а не сломается.
