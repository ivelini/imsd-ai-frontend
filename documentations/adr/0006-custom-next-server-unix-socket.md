# 0006. Приложение поднимает свой сервер Next и слушает unix-сокет панели

- **Статус:** Accepted
- **Дата:** 2026-10-06
- **Связанные ADR:** —

## Контекст
Прод фронта — сайт `aalyans74.ru` на сервере с ISPmanager, тип сайта «Node.js». Панель сама
запускает приложение (`npm start`, процессом pm2) и сама отдаёт ему запросы: nginx обслуживает
файлы из каталога сайта, а всё остальное проксирует на unix-сокет, путь к которому панель кладёт
в окружение процесса (`SOCKET`). Штатная команда `next start` слушает только TCP-пару
хост-порт — адрес сокета ей не отдать. Нужно было решить, как приложение принимает запросы.

## Решение
В корне репозитория — свой сервер `server.mjs`, запускается через `npm start` (`"start": "node server.mjs"`).
Он поднимает Next программно (`next({ dev: false, dir })`, штатный программный API) и слушает
unix-сокет из `SOCKET`; без `SOCKET` (локальный запуск) — TCP-порт. Владельцем процесса остаётся
панель: выкладка код обновляет и перезапускает процесс, но не заводит свой.

## Почему (альтернативы)
- **TCP-порт и прокси на порт** (как у соседнего сайта на том же сервере): панель так не умеет —
  это ручная правка конфигурации сайта админом хостинга, плюс каждый сайт занимает порт на общем
  сервере. Сокет — штатный механизм панели, работает без вмешательства в её настройки.
- **Режим `output: 'standalone'`**: генерируемый им сервер тоже слушает только TCP, а документация
  Next прямо говорит, что standalone и свой сервер несовместимы.
- **Статическая выгрузка (`output: 'export'`)**: невозможна — есть `rewrites` (`/api/*` → бэк) и
  серверные компоненты, читающие живые данные.
- **Держать приложение вне панели** (свой pm2 или supervisor): борьба за сокет и права с панелью,
  её кнопки «запустить/остановить» ломались бы; обновление панели затирало бы чужую настройку.

## Последствия
Своя точка входа дублирует небольшую часть работы `next start` — цена в файле на сорок строк,
зато приложение запускается штатными средствами панели и не требует правок конфигурации сервера.
От `output: 'standalone'` и связанных оптимизаций (мини-образ, standalone-режим) отказываемся;
пересмотрим при переезде на площадку, где приложение слушает TCP-порт (Docker, Vercel).
Контракт с панелью — два условия: переменная `SOCKET` в окружении процесса и каталог сайта как
рабочий каталог процесса; при обновлениях панели проверять, что оба сохранились (признак поломки —
страница-заглушка ISPmanager вместо сайта).
