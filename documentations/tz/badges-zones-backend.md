# ТЗ: стек баджей во всех ответах, где показывается товар

- **Статус:** бэк выполнил (27.10.2026) — баджи во всех зонах витрины; фронт подключил зоны
- **Дата:** 2026-10-23 (уточнено 27.10.2026)
- **Адресат:** бэкенд `imsd-backend` (Laravel)
- **Потребитель:** фронт `aalyans.ru` (Next.js) — карточка товара, листинг каталога,
  автоподбор, карточка модели
- **Связанные:** ADR бэка `common/0045-universalnye-badzhi.md` (универсальные баджи),
  ADR бэка `common/0048-badzhi-vne-keshey-obogrev-payload-posle-kesha.md` (баджи вне кешей),
  `documentations/tz/product-card-backend.md` (карточка товара)
- **Реализация фронта:** ядро `shared/types/badge.ts` + `shared/ui/Badge.tsx`; зоны — карточка
  товара, листинг, подбор по авто, карточка модели (планы закрыты 27.10.2026)

## 1. Цель

Бейдж (цветной ярлык с текстом, иконкой и ссылкой) должен показываться на любой витрине,
где показывается товар: не только в карточке, но и в листинге, подборе по автомобилю и
карточке модели. На момент постановки задачи (23.10.2026) стек баджей отдавался **только**
в карточке товара, поэтому в остальных зонах фронт показать было нечего.

## 2. Состояние на 27.10.2026 — бэк выполнил

- Поле `badges` бэк отдаёт **во всех зонах витрины**: карточка товара, листинг шин и дисков,
  офферы подбора по автомобилю, карточка модели. Формат элемента прежний:
  `{text, color, icon_key, link, owner_type, owner_name}`.
- Баджи **вне кешей** (ADR бэка `common/0048`): контроллер после `remember()` дописывает
  блок в payload (`BadgePayloadEnricher`), правка баджа видна сразу, инвалидация кешей
  баджей не нужна. Поэтому пункты 4–5 ниже («сброс кешей листингов при правке баджа»)
  сняты — нечего сбрасывать.
- Найденная при подключении фронта ошибка бэка: в зоне подбора энричер писал блок в
  `payload.sections`, а секции ответа лежат в `payload.data.sections` — баджи в офферах
  подбора не появлялись. Исправлено 27.10.2026 (`BadgePayloadEnricher::enrichByVehicle`),
  закрыто тестом `BadgeZonesTest::test_enriches_by_vehicle_offers`.
- `icon_key` в админке — свободный текст (`TextInput`, подсказка «Ключ из набора иконок
  фронта»); набора ключей на бэке нет.

## 2.1. Состояние на 23.10.2026 (до правки) — историческая часть

- Стек собирается `BadgeStackReader::stackFor(...)` — цепочка владельцев
  «товар → модель → бренд», дедуп по баджу (частный уровень выигрывает), порядок:
  уровень наследования, затем `sort` привязки. `badgeChain()` — у товара, модели и бренда.
- Поле `badges` есть только в `TireProductResource` и `WheelProductResource`
  (карточка товара). Формат элемента:
  `{text, color, icon_key, link, owner_type, owner_name}`.
- В листинге баджей нет: `TireListItemResource`, `WheelListItemResource` (этот же ресурс
  переиспользуется в `TireByVehicleResource`/`WheelByVehicleResource` для офферов),
  `TireModelCardResource`, `TireFilterValuesResource` — поля `badges` нет.
- Кеш: `BadgeCacheInvalidator` сбрасывает только кеши карточек товаров
  (`TireProductCacheService`, `WheelProductCacheService`). Комментарий в коде прямо
  фиксирует: «Листинги и фасеты баджи не содержат — их кеши не трогает». При появлении
  баджей в листинге это перестаёт быть верным.
- `icon_key` в админке — свободный текст (`TextInput`, подсказка «Ключ из набора иконок
  фронта»); набора ключей на бэке нет.

## 3. Что нужно от бэка

**Правило на фронте (ADR 0008):** если в `data` ответа пришёл объект `badges` — страница
выводит плашки. Значит, «зоны показа» определяет бэк: кладёшь поле в ответ — плашки
появились. Ниже — что нужно положить.

1. **Добавить `badges` в ответы витрин** — тем же форматом элемента, что и в карточке
   (контракт переиспользуемый; фронт рисует один компонент для всех зон).

   | Зона | Эндпоинт | Ресурс | Цепочка владельцев |
   |---|---|---|---|
   | Листинг шин | `GET /catalog/tires` | `TireListItemResource` | товар → модель → бренд |
   | Листинг дисков | `GET /catalog/wheels` | `WheelListItemResource` | товар → модель → бренд |
   | Подбор по авто | `GET /catalog/tires\|wheels/by-vehicle/…` | `TireListItemResource` / `WheelListItemResource` (офферы) | товар → модель → бренд |
   | Карточка модели | `GET /catalog/tire-models/{brand}/{model}` | `TireModelCardResource` | модель → бренд |
   | Карточка товара | `GET /catalog/tires\|wheels/…` | `TireProductResource` / `WheelProductResource` | уже есть |
   | Главная | `GET /service-page/main` | — | промо-бейджи сайта (владелец — сайт) |
   | Статья | `GET /articles/{id}` (когда появится) | — | статья |

2. **Промо-полоса (бейджи сайта).** Полоса в шапке («20% на услуги шиномонтажа», «Сборка
   комплекта бесплатно», «Хранение до монтажа бесплатно») больше не приходит из отдельного
   блока: фронт рисует её из `data.badges`. Нужен владелец уровня «сайт/магазин» в пивоте
   баджей (ADR бэка `common/0045`: «новая сущность получает баджи двумя строками») и
   эндпоинт с его стеком. Без него полосы не будет ни на главной, ни в каталоге, ни в
   корзине — а раньше она была на всех страницах.
3. **Главная: `attention_blocks` → `badges`.** Фронт перевёл мок главной на общий контракт
   `badges` (цвет-пресет `red|gold|green` вместо цвета-hex, `text` вместо `title`,
   `icon_key`, `link`). Ответ главной должен отдавать то же: иначе полоса главной
   соберётся не тем кодом. Старое поле `attention_blocks` тогда можно убрать.
4. **Сброс кешей листингов при правке баджа.** `BadgeCacheInvalidator` должен гасить
   ещё и `TireListCacheService`, `WheelListCacheService`, `TireModelCardCacheService`
   (и по аналогии — всё, где стек попал в payload). Иначе правка баджа в админке будет
   видна на карточке, но не в листинге — до истечения TTL.
5. **Привязки из панели** уже сбрасывают кеш карточек (`BadgesRelationManager`) — проверить,
   что после пункта 4 сбрасываются и кеши листингов.
6. **Набор ключей иконок.** Фронт рисует иконку по `icon_key` из набора шаблона:
   `red` | `gold` | `green` (те же три SVG, что в плашках преимуществ). Ключ неизвестен →
   фолбэк «иконка по цвету» (на бэке это не проверяется). Просим в админке заменить
   свободный текст на `Select` из трёх значений — иначе редактор может вписать что угодно
   (в дев-базе уже есть `icon_key = 'ывывыв'`).

## 4. Формат элемента (без изменений)

```jsonc
{
  "text": "Хит продаж",              // готовый текст плашки (бэк формирует)
  "color": "red",                    // 'red' | 'gold' | 'green' — пресет BadgeColor
  "icon_key": "red",                 // ключ иконки фронта: red | gold | green | null
  "link": "https://aalyans.ru/promo", // ссылка плашки или null
  "owner_type": "model",             // морф-алиас источника: product | model | brand
  "owner_name": "BEL-307"            // имя источника или null
}
```

- Фронт не строит словари отображения: текст, цвет-пресет и ссылка — готовые от бэка.
- `owner_type`/`owner_name` фронт не показывает (служебные поля для админки) — но оставляем
  в контракте: они помогают в отладке и в будущих зонах.

## 5. Вопросы к бэку — ответы (27.10.2026)

1. **Стек в листинге — та же сборка?** Да, но массовым вариантом: `BadgeStackReader::stacksFor`
   собирает стеки на набор id двумя запросами (активные баджи + привязки владельцев
   страницы), а не по одному на товар.
2. **Карточка модели:** цепочка «модель → бренд»; если у модели привязок нет, стек
   бренда — как в карточке товара.
3. **`promotion`:** остаётся отдельным полем от баджей, фронт его не рисует.
4. **Кеш листингов:** снимается — баджи вне кешей (ADR бэка `common/0048`), сбрасывать нечего.
5. **Владелец «сайт/магазин»:** не решён — промо-полоса главной живёт на моке
   (`HOME_DATA.badges`). Бэк-часть (владелец уровня «сайт» в пивоте баджей + эндпоинт)
   не делалась.

- Ядро готово: тип `Badge` (`shared/types/badge.ts`), чистая функция представления
  (`shared/ui/badgeView.ts`), компонент `shared/ui/Badge.tsx` (плашка `benefit
  benefit--{color}` + иконка + текст, полоса `.benefits`). Подключение зоны — одна строка
  `<Badges badges={…} />` в компоненте страницы.
- Порядок: карточка товара (поле уже есть) → листинг → автоподбор → карточка модели →
  главная (переименование `attention_blocks` → `badges`).

  27.10.2026); плашки в карточке — полосой над заголовком товара, на странице модели —
  перед заголовком модели.
- Осталось: главная — промо-полоса пока с мока (`HOME_DATA.badges`); бэк-часть (владелец
