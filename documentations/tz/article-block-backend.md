# ТЗ: блок статьи в зонах витрины (`article` в корне ответа)

- **Статус:** фронт реализован на моке (07.11.2026); бэк поле не отдаёт
- **Дата:** 2026-11-07
- **Адресат:** бэкенд `imsd-backend` (Laravel)
- **Потребитель:** фронт `aalyans.ru` (Next.js) — каталоги, подбор по авто, модель шин, карточки товара
- **План фронта:** `.claude/plans/article-block-zones.md`

## 1. Цель

В продуктовых зонах витрины нужен блок статьи — HTML-контент, привязанный к зоне через
маркировки (`article_markings`, ADR бэка `marking/0058`). Блок выводится, только если в корне
ответа есть объект `article`; поля нет или `null` — блока нет. Заголовок не нужен: фронт
рисует только HTML.

## 2. Контракт

Во всех перечисленных ответах — необязательное поле в корне, рядом с `data` и `meta`:

```json
{
  "data": { },
  "meta": { },
  "article": { "body": "<p>HTML RichEditor</p>" }
}
```

- `article` — объект `{ body: string }`; `body` — HTML из RichEditor, отдаётся как есть
  (фронт не экранирует и не парсит).
- Поля нет или `null` — блок не выводится.
- `article` живёт вне кешей (как баджи): правка статьи видна сразу, сброс кешей листингов
  не нужен. Место в коде — существующий `ContentPayloadEnricher`
  (`domains/Content/Marking/Services/Payload/ContentPayloadEnricher.php`).
- Если статье соответствует несколько маркировок — выбирает бэк; фронт рисует один блок,
  второй не нужен (при необходимости — расширение контракта до `articles: []`).

## 3. Эндпоинты

| # | Эндпоинт | Зона на фронте |
|---|---|---|
| 1 | `GET /api/catalog/tires` | каталог шин, внизу листинга |
| 2 | `GET /api/catalog/wheels` | каталог дисков, внизу листинга |
| 3 | `GET /api/catalog/tires/by-vehicle/{make}/{model}/{year}/{modification}` | подбор шин, уровень результата |
| 4 | `GET /api/catalog/wheels/by-vehicle/{make}/{model}/{year}/{modification}` | подбор дисков, уровень результата |
| 5 | `GET /api/catalog/tire-models/{brand}/{model}` | страница модели шин, внизу блока описания |
| 6 | `GET /api/catalog/tires/{brand}/{model}/{size}` | карточка шины, перед блоком «Наличие» |
| 7 | `GET /api/catalog/wheels/{brand}/{size}` | карточка диска, перед блоком «Наличие» |

Промежуточные уровни подбора (марки, модели, годы, модификации) `article` не отдают —
статья показывается только на уровне результата.

## 4. Поведение фронта

- `toArticleBlock(body.article)` → `null`, если объекта нет; иначе `{ contentHtml: body }`.
- Блок выводится в разметке зоны:
  - каталоги и подбор — после пагинации / SEO-блока внутри `.catalog-section`;
  - модель шин — последним элементом `.model-description`;
  - карточка — секцией перед `#availability`.
- Стили — общий `.article-content` (как на странице статьи): параграфы, `h3`, списки,
  картинки RichEditor по ширине колонки.

## 5. Проверка

- Ответ любого из семи эндпоинтов с `article: { body: "<p>Текст</p>" }` — блок виден в
  указанной зоне.
- Ответ без поля `article` и с `article: null` — блока нет на странице.
- HTML с картинкой (`<img width=… height=… style=…>`) — картинка не вылезает из колонки
  на ширинах 390–1920.
