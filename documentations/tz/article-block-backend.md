# ТЗ: блок статьи в зонах витрины (`article` в корне ответа)

- **Статус:** реализовано бэком и фронтом (10.11.2026); поле — строка HTML из текстов маршрутов
- **Дата:** 2026-11-07 (обновлено 10.11.2026)
- **Адресат:** бэкенд `imsd-backend` (Laravel)
- **Потребитель:** фронт `aalyans.ru` (Next.js) — каталоги, подбор по авто, модели шин и дисков, карточки товара
- **Планы фронта:** `.claude/plans/article-block-zones.md`, `.claude/plans/article-route-texts-frontend.md`

## 1. Цель

В продуктовых зонах витрины нужен SEO-текст маршрута — HTML-контент из админки
(«Тексты маршрутов», `article_routes.article`, ADR бэка `marking/0059`). Блок выводится,
только если в корне ответа есть ключ `article`; ключа нет — блока нет. Заголовок не нужен:
фронт рисует только HTML.

## 2. Контракт

Во всех перечисленных ответах — необязательное поле в корне, рядом с `data` и `meta`:

```json
{
  "data": { },
  "meta": { },
  "article": "<p>HTML RichEditor</p>"
}
```

- `article` — **строка** HTML из RichEditor, отдаётся как есть (фронт не экранирует
  и не парсит). Порядок склеенных привязок и удаление дублей — на бэке.
- Ключа нет, если текста для страницы нет (не `null`, не `""`).
- Текст зависит от маршрута **и фильтров**: точная привязка вытесняет общую, привязки
  с разными параметрами складываются; условия могут включать город.
- `article` живёт вне кешей: правка текста в админке видна сразу, сброс кешей листингов
  не нужен.
- Списка текстов нет — только одна строка.

## 3. Эндпоинты

| # | Эндпоинт | Зона на фронте |
|---|---|---|
| 1 | `GET /api/catalog/tires` | каталог шин, внизу листинга |
| 2 | `GET /api/catalog/wheels` | каталог дисков, внизу листинга |
| 3 | `GET /api/catalog/tires/by-vehicle/{make}/{model}/{year}/{modification}` | подбор шин, уровень результата |
| 4 | `GET /api/catalog/wheels/by-vehicle/{make}/{model}/{year}/{modification}` | подбор дисков, уровень результата |
| 5 | `GET /api/catalog/tire-models/{brand}/{model}` | страница модели шин, внизу блока описания |
| 6 | `GET /api/catalog/tires/{brand}/{model}/{size}` | карточка шины, перед блоком «Наличие» |
| 7 | `GET /api/catalog/wheels/{brand}/{size}` | карточка диска, перед блоком «Наличие» |
| 8 | `GET /api/catalog/wheel-models/{brand}/{model}` | страница модели дисков, внизу блока описания |

Промежуточные уровни подбора (марки, модели, годы, модификации) и id-фолбэк подбора
`article` не отдают — текст показывается только на уровне результата slug-пути.

## 4. Поведение фронта

- `toArticleBlock(body.article)` → `null`, если ключа нет, `null` или пустая строка;
  иначе `{ contentHtml }`.
- Блок выводится в разметке зоны:
  - каталоги и подбор — после пагинации / SEO-блока внутри `.catalog-section`;
  - модели шин и дисков — последним элементом `.model-description`;
  - карточка — секцией перед `#availability`.
- Стили — общий `.article-content` (как на странице статьи): параграфы, `h2`/`h3`, списки,
  картинки RichEditor по ширине колонки.

## 5. Проверка

- Ответ любого из восьми эндпоинтов с `article: "<p>Текст</p>"` — блок виден в указанной зоне.
- Ответ без ключа `article` — блока нет на странице (пустой заглушки нет).
- HTML с заголовком `<h2>` — выглядит заголовком статьи, а не заголовком страницы каталога.
- HTML с картинкой (`<img width=… height=… style=…>`) — картинка не вылезает из колонки
  на ширинах 390–1920.
