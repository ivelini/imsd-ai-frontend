# ТЗ: слаги Vehicle в URL авто-подбора

- **Статус:** реализовано бэком 20.10.2026 (слаги в ответах, вложенные справочники,
  композитный результат, numeric fallback); фронт переведён на слаги, старые
  numeric URL редиректят 307
- **Дата:** 2026-10-20
- **Адресат:** бэкенд `imsd-backend` (Laravel)
- **Потребитель:** фронт `/catalog/tires/auto`
- **Связанное ТЗ:** `auto-selection-backend.md` (методы чтения подбора; реализованы)

## 1. Цель

Заменить числовые `id` в публичном URL авто-подбора на человекочитаемые слаги:
`/catalog/tires/auto/{makeSlug}/{modelSlug}/{year}/{modificationSlug}`.

Пример: сейчас `/catalog/tires/auto/1/6/1999/75` (Acura / Integra / 1999 / 1.8i);
нужно `/catalog/tires/auto/acura/integra/1999/1-8i`.

## 2. Текущее состояние (проверено)

- В `vehicle_makes`, `vehicle_models`, `vehicle_modifications` **колонок `slug` нет**
  (проверка `information_schema.columns` — 0 строк).
- Публичные методы уже читают Vehicle и отдают `id`/`name`/`label`; результат подбора —
  `GET /api/catalog/tires/by-vehicle/{modification}` (числовой id).
- Импорт CSV (`VehicleRowProcessor`) создаёт марку/модель/модификацию через
  `firstOrCreate`; слаги не генерирует.

## 3. Правила слагов

Слаги генерируются один раз и дальше **не меняются** при переимпорте (стабильность URL).
Транслитерация — `Str::slug($name)` (кириллица → латиница); пустой результат —
fallback `item-{id}`.

### 3.1. Марка

- `slug = Str::slug(name)`; `Alfa Romeo` → `alfa-romeo`.
- Уникален глобально; коллизия после транслитерации → суффикс `-2`, `-3`.

### 3.2. Модель

- База: `slug(name)`; уникален в рамках марки (`unique(make_id, slug)`).
- Если база занята другой моделью той же марки (разные поколения):
  1. `slug(generation)`, если поколение непустое и не равно имени;
  2. иначе `slug(name + " " + generation)`;
  3. остаточная коллизия → `-2`, `-3`.
- Примеры (Acura):
  - `CDX` / `CDX` → `cdx`;
  - `CL` / `CL` → `cl`, `CL` / `CL II` → `cl-ii`;
  - `Integra` / `Integra` → `integra`, `Integra IV` → `integra-iv`,
    `Integra Type-R` → `integra-type-r`;
  - `MDX` → `mdx`, `MDX II (YD2)` → `mdx-ii-yd2`, `MDX III (YD3)` → `mdx-iii-yd3`,
    `MDX IV` → `mdx-iv`.
- Пустое поколение или поколение = имя — база `slug(name)`.

### 3.3. Модификация

- База: `slug(name)`; уникален в рамках `(model_id, year)` — год входит в URL,
  глобальная уникальность не нужна.
- Примеры: `1.8i` → `1-8i`; `1.5 T` → `1-5-t`; `2.0i` → `2-0i`; `3.5 V6` → `3-5-v6`.
- Коллизия после транслитерации (разные имена дали один слаг) → `-2`, `-3`.
- Год в слаге не дублируется — он отдельный сегмент URL.

## 4. Схема и импорт

Почему колонки, а не вычисление слага на чтении: слаг — стабильный ключ URL
(переименование не должно ломать ссылки), а разрешение по слагу — индексный запрос,
а не сканирование с разрешением коллизий на каждом запросе.

1. Миграции:
   - `vehicle_makes.slug` (string, nullable → NOT NULL, unique);
   - `vehicle_models.slug` (string, nullable → NOT NULL, unique `make_id+slug`);
   - `vehicle_modifications.slug` (string, nullable → NOT NULL,
     unique `model_id+year+slug`).
2. Генератор — сервис `VehicleSlugGenerator` (чистые правила + доступ к занятым слагам),
   пригодный для импорта, миграции и artisan-команды.
3. Импорт: `VehicleRowProcessor` при **создании** марки/модели/модификации передаёт
   слаг; существующие строки (`firstOrCreate`) слаг не меняют.
4. Бэкфилл существующих строк: миграция или команда
   `vehicle:backfill-slugs` (идемпотентная, порядок по `id`), затем NOT NULL и
   уникальные индексы. Данные в dev уже есть (~452 модификации); на проде — проверить
   количество до/после.
5. Переимпорт CSV не обязателен: слаги существующих строк бэкфиллятся; новые строки
   получают слаги при импорте. Повторный импорт не должен менять уже выданные слаги
   и не должен создавать дубли.

## 5. API

### 5.1. Ответы

Во всех ответах Vehicle добавить `slug` рядом с `id`:
- марки `{id, slug, name}`;
- модели `{id, slug, name, label, generation}`;
- модификации `{id, slug, name, label}`;
- результат подбора: `vehicle.make/model/modification` — с `slug`.

### 5.2. Справочники (канонические пути)

- `GET /api/reference/vehicle/makes?category=tire` — без изменений пути.
- `GET /api/reference/vehicle/makes/{make}/models?category=tire` — `{make}` слаг.
- `GET /api/reference/vehicle/makes/{make}/models/{model}/years?category=tire` —
  оба слага (сейчас путь без `make` — привести к вложенному, чтобы слаг модели был
  однозначен в рамках марки).
- `GET /api/reference/vehicle/makes/{make}/models/{model}/modifications?year=&category=tire`.

Разрешение параметров: слаг — канонический ключ; числовой `id` — **fallback** для
старых ссылок (route binding/resolver принимает оба). Неизвестный слаг/id → 404.

### 5.3. Результат подбора

- Канонический путь:
  `GET /api/catalog/tires/by-vehicle/{make}/{model}/{year}/{modification}`
  (`{year}` — 4 цифры; остальные — слаги).
- Старый `GET /api/catalog/tires/by-vehicle/{modification}` (числовой id) —
  оставить как deprecated-алиас на переходный период: он нужен фронту, чтобы
  резолвить старые числовые URL в слаги и делать редирект.
- Ответ — прежний контракт (`vehicle`, `sections`, `meta`), плюс слаги.
- Кэш — по `modification_id` (резолвится из слагов), ключ можно не менять.
- SEO/H1 — без изменений (имена, не слаги).

## 6. Совместимость URL

- Канонический URL фронта — со слагами.
- Старые числовые URL (`/auto/1/6/1999/75`) должны перенаправляться (301/redirect)
  на канонический слаг-URL; фронт делает это после резолва через deprecated-алиас
  или справочники с fallback по id.
- Слаги регистрозависимы (нижний регистр); верхний регистр → 404 или редирект на
  нижний — выбрать и зафиксировать (рекомендуется 404).

## 7. Тесты и приёмка

1. Unit `VehicleSlugGenerator`: правила марок/моделей/модификаций, коллизии,
   кириллица, пустой слаг, стабильность.
2. Feature:
   - ответы справочников и результата содержат `slug`;
   - слаг-пути возвращают те же данные, что числовые id;
   - числовой fallback работает;
   - неизвестный слаг → 404;
   - повторный импорт не меняет слаги и не создаёт дублей.
3. Бэкфилл: до/после — одинаковое количество строк, все слаги непустые и уникальны
   в своих областях.
4. Scramble-экспорт `public-api.json` содержит новые пути и поля.
5. Живой смоук: `/api/reference/vehicle/makes/acura/models` → `integra`, `integra-iv`,
   `integra-type-r`; результат
   `/api/catalog/tires/by-vehicle/acura/integra/1999/1-8i` = результат по id 75.

## 8. Вне объёма

- Переименование слагов через админку (в Vehicle админки нет).
- Слаги для товаров/брендов каталога — уже есть.
- Результат подбора дисков (фаза 2) — использует ту же схему слагов, когда появится.

## 9. Вопросы к бэку

1. Вложенный путь `makes/{make}/models/{model}/years` — подтвердить (ломает текущий
   `/models/{model}/years`, но фронт ещё не выложен; альтернатива — глобально
   уникальные слаги моделей, длиннее).
2. Числовой fallback в route binding — подтвердить (нужен для редиректа старых URL).
3. Deprecated-алиас `by-vehicle/{modification}` — оставить на один релиз или убрать
   сразу (если редиректы не нужны).
