# 0003. Пагинация типоразмеров модели: диаметр в URL + «Показать ещё»

> Source: documentations/adr/0003-model-sizes-pagination.md (проектный файл)
> Collected: 2026-08-19
> Published: 2026-08-12

- **Статус:** Accepted
- **Дата:** 2026-08-12
- **Связанные ADR:** 0002

## Контекст
Страница модели `/tires/[modelSlug]` рендерила все типоразмеры разом: в моке 160–842 карточки (viatti — 842, ~94 на диаметр). Тяжёлый DOM, скролл в километр, нереалистично для продакшена.

## Решение
Гибрид: первичная навигация — вкладки по диаметрам, выбранный диаметр живёт в URL (`?diameter=r17`, та же идея, что фильтры каталога в ADR 0002); внутри секции — «Показать ещё» по 24 карточки (клиентское состояние, сброс при смене диаметра). SSR первого экрана совпадает с гидрацией (24 карточки + кнопка), вкладки — кнопки + `router.replace` без полного навигационного цикла.

## Почему (альтернативы)
- Классическая серверная пагинация `?page=N` — теряется группировка по диаметрам, переделка вёрстки `ModelSizes`.
- Чистый «Показать ещё» без диаметра — на 842 карточки 28 кликов, а URL не фиксирует позицию.
- Только вкладки диаметров — внутри больших диаметров (135 шт.) всё ещё простыня.
Пагинация и фильтрация остаются на бэке при подключении API: фронт шлёт `diameter`/`page` — текущая схема не противоречит контракту.

## Последствия
DOM страницы ограничен (24 карточки + кнопка), URL модели переиспользуем. «Показать ещё» — клиентское состояние, не SEO-фактор: поисковик видит первые 24; для SEO-каталожной выдачи это осознанный компромисс. При подключении API размер батча (24) и механика кнопки могут переехать на бэк-контракт (items + has_more). Вкладки-диаметры заменяют мок-якоря `#diameter-rXX` — глубокие ссылки на диаметр изменили формат.
