# Выкладка: health-check и basic-auth на витрине

> Source: инцидент выкладки 2026-11-25 (лог GitHub Actions, vhost `/etc/nginx/vhosts/aalyans74_ru/aalyans74.ru.conf`, `documentations/operations.md`, `.github/workflows/deploy.yml`)
> Collected: 2026-11-25
> Published: 2026-11-25

## Симптом

Выкладка на прод падала на шаге «Проверить, что приложение живо»:

```
Приложение отвечает через сокет
curl: (22) The requested URL returned error: 401
Сайт https://aalyans74.ru/ — 401
```

Сокет-проверка проходила, домен отдавал 401 — сайт закрыт HTTP Basic Auth.

## Причина

- В vhost панели включён `auth_basic "Restricted"` с файлом `/etc/nginx/.htpasswd-aalyans74`;
  ответ домена — `401`, `WWW-Authenticate: Basic realm="Restricted"`. Бэкап конфига датирован
  2026-11-11 — защита включена около 11.11.
- Health-check выкладки после переключения релиза делал `curl -fsS` по домену: `-f` считает 401
  ошибкой, шаг падал (exit 22) уже **после** переключения ссылки и `pm2 restart`.
- Шаг «Убрать старые релизы» стоит после проверки и не выполнялся: с 11.11 релизы копились
  (к 25.11 семь каталогов, 3.1 ГБ), 25.11 диск сервера заполнился до 0 байт.
- Следствия того же дня: `npm ci` в следующей выкладке упал с `ENOSPC`; PostgreSQL-кластер
  `16/main` остановился, API отдавал 500 на всех DB-маршрутах. Старые релизы и кэш npm удалены,
  место освобождено (1.7 ГБ).

## Решение

- Health-check принимает `200` и `401`: 401 при basic-auth означает, что nginx и TLS ответили,
  а приложение уже проверено через unix-сокет (ответ содержит `/_next/static/`). Любой другой
  код валит выкладку.
- Защита сайта не менялась. Когда basic-auth снимут, проверка пройдёт по 200 без правок.
- Правило на будущее: сокет-проверка — про приложение, домен-проверка — про nginx/TLS/прокси;
  staging-защита не должна делать выкладку красной.
