# React-порт записи на шиномонтаж на живом API (30.09.2026)

> Source: план `.claude/plans/booking-react-port.md` + реализация 30.09.2026 (код в рабочем дереве) + живая проверка потока в браузере
> Collected: 2026-09-30
> Published: 2026-09-30

Макет-эталон `.template/booking/` (11 страниц, перенесён 12.09.2026) превращён в рабочий
React-поток на живом API бэка: пять роутов, домен `src/features/booking/`, стили домена
в `src/app/style.css`. Раздел «Мои записи» (`my/*`) в фазу не входит — публичного API нет.

## Контракт API (группа «Запись на шиномонтаж»)

| Шаг | Эндпоинт | Ответ |
|-----|----------|-------|
| Календарь | `GET /api/booking/slots?date_from&date_to` | `{data:{days:{"Y-m-d":bool}}}` — bool = есть открытый слот; прошлое и за горизонтом тоже `false` |
| Часы дня | `GET /api/booking/slots/{date}` | `{data:{slots:[{hour,is_closed}]}}` — только существующие часы; `is_closed` → чип «занято» |
| Услуги | `GET /api/booking/catalog?radius&car_type` | `{data:{services:[{id,name,base_price,has_rules,unit_price?}],complexes:[{id,name,service_ids}],rules:{radius:[{value,label}],car_type:[{value,label}]}}}` |
| Код | `POST /api/booking/code {phone}` | `{data:{retry_after:int}}` — длительность кулдауна (60 с), не остаток; 429 если рано |
| Запись | `POST /api/booking/confirm {...}` | 201 `{data:{id,number,date,start_time,status,radius,car_type,plate,total_price,user,items}}`; 200 — повторный submit тем же кодом |
| Справочник | `GET /api/reference/booking` | адрес и телефон мастерской, срок жизни кода, лид-тайм, горизонт, количество по умолчанию |

Ошибки — `DomainException` → `{message, code}`; коды `BookingErrorCode` (`booking.*`, ADR 0027 бэка):
`code_expired`, `code_invalid`, `slot_unavailable`, `slot_time_taken`, `code_cooldown` (429,
`retry_after` + заголовок `Retry-After`), `price_rule_missing`, `phone_invalid`, `date_invalid`.
Тексты — для человека и могут меняться, различать состояния можно только по коду.

### Ловушки контракта, найденные при сверке

- `quantities` — **объект с ключом `service_id`**, а не позиционный массив: массивом PHP
  разложит его по порядку и `PriceCalculator` молча подставит количество 1 — цена уедет без ошибки.
- `plate` и `quantities` контроллер читает безусловно: пропуск ключа → 500 (не 422), госномер
  без значения уходит как `null`.
- **Каталог принимает радиус и тип только парой** (валидация `required_with`): запрос с одним
  параметром отвечает 422; с парой — отдаёт `unit_price`, без пары — `base_price`.
- `total_price`, `base_price`, `unit_price`, `price` — копейки; `number` записи — «TS-» + id
  с ведущими нулями (человекочитаемый номер в API есть с 30.09.2026).

## Решения

1. **Черновик записи — в sessionStorage**, в URL только шаг (ADR 0005). Прямой заход на шаги 2–4
   с неполным черновиком уводит на шаг 1; смена даты или часа сбрасывает выданный код.
2. **Отказы шага 4 — состояния экрана, а не роуты** (в макете это отдельные страницы):
   «код устарел» и «время занято» приходят одним статусом 409 и различаются только машинным кодом.
3. **Экран успеха — отдельный роут со снимком** ответа в sessionStorage; черновик при успехе
   очищается. Прецедент — `/order/[id]`.
4. **Точка входа — пункт «Шиномонтаж» в шапке** (данные шапки из `GET /api/service_pages`);
   тот же пункт добавлен в шапку 31 файла `.template/*`, иначе макет перестал бы быть эталоном.
5. **Деньги:** цены держатся в копейках до отображения; `shared/lib/money.ts` — `formatMoney`
   (копейки) и обёртка `formatPrice` (рубли); восемь копий `formatPrice` в проекте сведены на импорт.
6. **Пара радиус+тип обязательна на шаге 2**: подтверждение бэка без неё не проходит (валидация),
   поэтому кнопка «Продолжить» ждёт пару; до выбора обеих цен показываются базовые.

## Что нашла живая проверка в браузере

- Запрос каталога с одним параметром (радиус без типа) отвечал 422 и **гасил список услуг**;
  хук шлёт пару или ничего + `keepPreviousData`, чтобы смена радиуса не мигала списком.
- При ошибке валидации на экран тёк технический ключ `validation.required` — ответ с `errors`
  без машинного кода сводится к общей формулировке.
- Действие при отказе шага 4 зависит от состояния: «время занято» уводит на выбор времени,
  «код истёк/не найден» — на повторную выдачу кода.

## Проверки

- Юнит-тесты: 16 в пяти файлах (`tests/unit/booking*.test.ts`) по тест-листу плана — красный
  прогон до файлов реализации, зелёный после; полный набор 73 теста.
- Сквозной прогон в браузере на живом API: время → услуги → данные → код → успех, записи
  `TS-000040` и `TS-000041`; экран отказа «код не найден»; мобильное разрешение 390 px;
  ошибок консоли и сети нет.
- Макет: `check-all.mjs` — 0 переполнений и 0 битых ссылок (27 страниц × 5 разрешений).

## Что осталось вне фазы

- Раздел «Мои записи» (`my/*`, 4 страницы макета) — публичного API нет: ни списка записей,
  ни отмены, ни входа по коду.
- Стили `my/*` и мёртвый `.map-placeholder` оставлены в `.template/assets/css/style.css`.
- Состояние «код устарел» живьём не воспроизводилось (срок кода 15 минут) — закрыто юнит-тестами.
