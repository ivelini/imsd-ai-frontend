# Макет страницы ошибки «Сервис временно недоступен» (.template/error.html)

> Source: Сессия в проекте template (роль: создать страницу-макет ошибки в .template); файлы .template/error.html, .template/assets/img/error.svg, блок .error-* в .template/assets/css/style.css
> Collected: 2026-10-16
> Published: 2026-10-16

Задача: статичная страница-макет, показываемая при недоступности API бэка и любых
нештатных ошибках сервера. Требования: чисто HTML без логики (без JS), взять
основной дизайн — шапку и подвал из существующих страниц мокапа; текст про
недоступность сервиса и работы по восстановлению; тематическая картинка —
опционально.

## Что создано

- `.template/error.html` (28-я страница мокапа). Структура: стандартный каркас
  `app → wrapper → header → section → footer`. Шапка и подвал скопированы 1-в-1 из
  `.template/index.html` (проверено диффом — блоки идентичны); скрытые оверлеи
  (два `catalog-hidden-menu`, `geo-wrapper`) и гео-окно намеренно не включены — без
  JS они мертвы, а страница должна быть чистой HTML. `lang="ru"`.
- Контент: секция `.error-section.container` → карточка `.error-card` (белая,
  max-width 680, тень — паттерн `.booking-success`) с картинкой, заголовком
  `<h1>` «Сервис временно недоступен» и двумя абзацами: «Произошёл технический
  сбой — сайт временно не может обрабатывать запросы. Наши специалисты уже
  работают над восстановлением»; «Пожалуйста, попробуйте зайти позже. Приносим
  извинения за доставленные неудобства». Кнопок нет — без JS обновление страницы
  не организовать (чистый HTML).
- `.template/assets/img/error.svg` — тематическая картинка: шина с протектором
  и спицами + красный знак «!» (цвета из токенов: #303030, #5a5a5a, #ededed,
  #c5c5c5, #dd062a). Подключена как `<img class="error-picture">`.
- Стили — блок `.error-section / .error-card / .error-picture / .error-title /
  .error-text` в конце `.template/assets/css/style.css` с пометкой 16.10.2026
  (+ адаптация ≤639px: паддинги, картинка 160px, заголовок 24px). Правило
  ui-porting: стили непортированной страницы живут в .template до React-порта.
- Регистрация в инструментах: `/ .template/error.html` добавлен в
  `.claude/verify/verify.mjs` и `.claude/verify/check-all.mjs`; счёт страниц
  мокапа в CLAUDE.md 27 → 28.

  нет, картинки целые, заголовок на месте; шапка/подвал совпадают с index.html

## Расхождение с реализованной страницей ошибки

Страница в приложении (`src/app/global-error.tsx`, см.
[backend-error-fallback](../../wiki/concepts/backend-error-fallback.md)) по
согласованному решению — **без шапки и подвала** и без единого обращения к API:
любой фетч на странице-крахе бессмыслен и дал бы пустой город. Новый макет
`error.html` устроен иначе — с шапкой и подвалом (они статичны в мокапе, но при
порте потянут живой `useGeo`). Макет в Next **не портирован**, приложение не
менялось; это дизайн-эталон, возможно — альтернатива для случая, когда страницу
ошибки отдаёт статика (например, при мёртвом сервере Next), а не React-граница.
Что с ним делать — решение пользователя; до него расхождение фиксируем, а не
разрешаем.
