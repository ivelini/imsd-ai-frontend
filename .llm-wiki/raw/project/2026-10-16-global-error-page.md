# Страница ошибки при недоступном бэке (global-error)

> Source: План .claude/plans/backend-error-fallback.md, прогоны на прод-сборке (фронт aalyans.ru)
> Collected: 2026-10-16
> Published: 2026-10-16

При 5xx или недоступности Laravel-бэка страницы с живыми фетчами падали в дефолтный
экран Next («Application error…», без шапки и подвала). Требование пользователя:
страница ошибки не должна зависеть от API вообще («если нет ответа от бэка, это уже
не сайт»), с кнопками «Обновить» и «На главную».

## Кто зависит от живого бэка (на 16.10.2026)

- `getGeo()` → `GET /api/reference/city` — ждут 6 серверных страниц: каталог шин
  (params + auto), каталог дисков (params + auto), страница модели, страница
  типоразмера. Одна 500 по справочнику городов роняет все шесть.
- `getCatalogFilters()` → `/api/reference/filter/tire` и `getCatalogProducts()` →
  `/api/catalog/tires` — каталог шин (в т.ч. `generateMetadata` ходит тем же fetch).
- Запись на шиномонтаж — клиентские запросы (React Query): доменные отказы разобраны
  `mapBookingError`, общий 500 даёт тихие пустые списки (долг, вне области).
- Клиентский `useGeo` в шапке при недоступном бэке — пустой город без падения (долг, вне области).

## Решение

- `src/app/global-error.tsx` (новый) — верхняя React-граница Next, **заменяет root
  layout целиком**: свои `<html lang="ru">/<body>`, `import "./style.css"` (глобальные
  стили в global-error не наследуются), `<title>` React-элементом (metadata-экспорт
  в client-компоненте невозможен). Ловит и ошибки страниц, и ошибки root layout.
- Почему не `error.tsx` внутри обвязки: root layout тянет живой `useGeo` — страница
  ошибки всё равно делала бы запрос к API и показывала пустой город.
- Кнопки: «Обновить» → `window.location.reload()` (полная перезагрузка; `unstable_retry`
  отклонён — помечен unstable и делает «мягкий» повторный рендер); «На главную» —
  обычная ссылка `<a href="/">` (полная загрузка не зависит от состояния рантайма;
  осознанное отключение правила `@next/next/no-html-link-for-pages`).
- Стили `.error-page*` — в конец `src/app/style.css` с пометкой 15.10.2026 (страницы
  в макете нет — кастомная, как корзина и ЛК).
- Единое поведение без точечных смягчений: мок-страницы с живым `getGeo` (модель,
  типоразмер, диски) при 500 города тоже показывают страницу ошибки.

## Прогоны

- Красный (до правки, заглушка 500): `/catalog/tires` → дефолтный экран Next
  («Runtime Error: getCatalogProducts: HTTP 500»); `/tires/viatti-strada-2/185-55-r15-84h`
  → 500; `/`, `/articles`, `/cart` → 200.
- Зелёный (прод-сборка, `BACKEND_URL` на переключаемую заглушку): прямой заход →
  500 + своя страница (обе кнопки, ни одного запроса к /api); «Обновить» после
  оживления бэка → 12 карточек; клиентский переход из меню → страница ошибки,
  «На главную» возвращает; мок-страницы живы; мок-страница с живым гео → страница ошибки.
- Проверки: `npm test` 80 passed, `tsc --noEmit` чисто, `eslint` 0 ошибок.

## Поведение Next 16.2

500-ответ отдаёт оболочку `__next_error__`; сама страница ошибки отрисовывается
клиентом (у дефолтной страницы Next то же самое) — без JS виден пустой документ.
Статус ответа — 500 (годится для мониторинга).

## Вне области

404-страница (`notFound()` даёт дефолт Next), тихие пустые состояния booking,
пустой город в шапке при недоступном гео, `error.tsx` для внутренних границ.
