# Контракт API: данные для отображения формирует бэк

> Source: .claude/rules/api-contract.md (проектный файл)
> Collected: 2026-08-19
> Published: Unknown

1. **Все отображаемые данные приходят от бэкенда** в готовом для рендера виде: `{ label, value }` для опций фильтров/селектов, тексты, заголовки, метки. Фронт не строит словари и маппинги для отображения.
2. **Если для отображения требуется словарь или хардкод-маппинг на фронте** (например, `season: "summer"` → «Летняя» вручную) — это **недоработка API бэкенда**. Такие места подсвечивать пользователю и требовать у бэкенда label/готовые строки.
3. Мок-слой (`src/data/*`) имитирует ответ бэкенда: label формируется в моке так, как это сделает API. Фронт-компоненты работают только с готовыми `{ label, value }`.
4. `value` — всегда латинский slug/строка, совпадает 1:1 с сегментами/query URL (`winter`, `r15`, `viatti`, `russia`). Никаких русских значений в URL и в value.
5. Сопоставление с URL — прямое сравнение `option.value === segment`, без маппингов.
