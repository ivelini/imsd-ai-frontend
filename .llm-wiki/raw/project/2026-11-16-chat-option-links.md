## Контракт бэка

`options: [{label, text?, url?}]` у реплики ассистента. У варианта либо `text` — реплика,
которая уходит в POST как будто напечатана, либо `url` — относительный путь каталога
с параметрами и городом; клик по `url` — переход, POST не вызывается. `label` — подпись
в обоих случаях. Показывать только у последней реплики; после клика кнопки не активны.
`url` строит бэкенд по инструментам (`search_vehicle`, `vehicle_tires`, `vehicle_wheels`,
`search_tires`), модель их не сочиняет.

## Решение фронта (пользователь 16.11.2026)

- Переход — в той же вкладке без перезагрузки: `router.push(url)`; если адрес совпадает
  с текущим (`pathname + search`) — `router.refresh()`, иначе push по тому же пути данные
  не обновит (`isCurrentLocation` в `features/chat/lib/options.ts`).
- Окно чата остаётся открытым: виджет живёт в root layout, layout не перемонтируется;
  страница каталога перезапрашивается на сервере (RSC).
- После клика варианты реплики скрываются: состояние `dismissedMessageId` в `ChatWindow`
  (при переходе последняя реплика остаётся `assistant`, правило «только последняя» само
  кнопки не уберёт).
- Ссылка — семантический `<a href>` с перехватом только левого клика без модификаторов:
  средний/ctrl/shift/alt-клик работают нативно (новая вкладка).
- `text`-варианты работают как раньше: `sendMessage(text, false)`, `disabled` при отправке,
  после успеха варианты исчезают.

## Проверки

- Тесты: `test_url_option_is_returned` (вариант только с `url` не выбрасывается),
  `test_current_location_detection` (совпадение адреса → refresh, иначе push).
- Прогоны: красный 1 упавший тест → зелёный 33 файла / 181 тест; tsc чисто; lint 0 ошибок.
- Живой прогон (dev, `?city=ekaterinburg`): «Найди зимние шины 205/55 R16 в наличии» →
  `<a>` «Открыть каталог» с `href=/catalog/tires/winter/w205/p55/r16?city=ekaterinburg`;
  клик → URL каталога сменился, окно чата открыто, вариантов 0, POST не отправлялся.
