# Город как контекст запроса: резолв фронтом, city в URL (ADR 0004)

> Sources: ADR 0004, 2026-08-14
> Raw: [ADR 0004](../../raw/project/2026-08-19-adr-0004-city-request-context.md)

## Overview

Цены, наличие и SEO-контент зависят от города. Решение: фронт авторитетен — город всегда доводится до URL как `?city=`, в сигнатурах геттеров это отдельный аргумент (`getCatalogProducts(filter, city?)`), не поле `FilterState`.

## Решение

- Город в URL: вход по ссылке, выбор в GeoPopup, восстановление из стора при заходе без параметра (`CityHydrator` синхронизирует URL↔store через чистую `citySyncAction`, город в localStorage).
- Смена города — RSC-навигация (`router.push`): серверные геттеры перевыполняются с новым городом.
- `city` — контекст запроса, а не критерий товара: не входит в `FilterState`, конфиги URL и сравнения фильтров.

## Почему

- Резолв бэком (IP/cookie): URL лишается города — страдает SEO (нет канонических URL), лейблы могут разойтись с городом бэка.
- `city` внутри `FilterState`: засорение модели критерия товара контекстом запроса (useFilterStore, `segmentOrder`/`extraQueryFields`, сравнения фильтров).

## Последствия

URL — единственный источник истины: ссылки переживают перезагрузку, кэш/CDN дружат с параметром. Смена города = серверный рендер заново (мигание принято). Бэк получает `city` как query-параметр, без параметра применяет дефолт. Пересмотрим при геолокации по IP без URL — контракт допускает резолв бэком при пустом параметре.
