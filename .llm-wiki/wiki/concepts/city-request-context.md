# Город как контекст запроса: city в URL, резолв бэком (ADR 0004, обновлён 21.08.2026)

> Sources: ADR 0004, 2026-08-14; catalog-tires-live-api, 2026-08-21
> Raw: [ADR 0004](../../raw/project/2026-08-19-adr-0004-city-request-context.md); [catalog-tires-live-api](../../raw/project/2026-08-21-catalog-tires-live-api.md)

## Overview

Цены, наличие и SEO-контент зависят от города. Решение: фронт авторитетен — город всегда доводится до URL как `?city=` (слаг), в сигнатурах геттеров это отдельный аргумент (`getCatalogProducts(filter, city?)`), не поле `FilterState`. С 21.08.2026 **резолв города выполняет бэк**: листинг каталога принимает `city=<слаг>` и сам находит город (приоритет: `city_id` → слаг → дефолт `config/shop.php`), фронт не резолвит id и не делает предварительный запрос гео.

## Решение

- Город в URL: вход по ссылке, выбор в GeoPopup, восстановление из стора при заходе без параметра (`CityHydrator` синхронизирует URL↔store через чистую `citySyncAction`, город в localStorage).
- Смена города — RSC-навигация (`router.push`): серверные геттеры перевыполняются с новым городом.
- `city` — контекст запроса, а не критерий товара: не входит в `FilterState`, конфиги URL и сравнения фильтров.

## Почему

- Резолв бэком (IP/cookie): URL лишается города — страдает SEO (нет канонических URL), лейблы могут разойтись с городом бэка.
- `city` внутри `FilterState`: засорение модели критерия товара контекстом запроса (useFilterStore, `segmentOrder`/`extraQueryFields`, сравнения фильтров).

## Последствия

URL — единственный источник истины: ссылки переживают перезагрузку, кэш/CDN дружат с параметром. Смена города = серверный рендер заново (мигание принято). Бэк получает `city` как query-параметр, без параметра применяет дефолт. С 21.08.2026 резолв слага — на бэке (несуществующий слаг → дефолт, не 422); фронт для листинга не резолвит id. Остаётся гео-справочник (`/api/reference/city`) для шапки/попапа и cityLabel. Пересмотрим при геолокации по IP без URL — контракт допускает резолв бэком при пустом параметре.
