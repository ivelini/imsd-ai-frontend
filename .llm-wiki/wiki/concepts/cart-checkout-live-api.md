# Корзина и оформление заказа на живом API

> Sources: Корзина и оформление заказа на живом API, 2026-11-24; контракт `checkout-frontend.md` бэка, 2026-11-24; Личный кабинет на живом API, 2026-11-24
> Raw: [2026-11-24-cart-checkout-live](../../raw/project/2026-11-24-cart-checkout-live.md); [2026-11-24-account-auth-live](../../raw/project/2026-11-24-account-auth-live.md)

## Overview

С 24.11.2026 корзина и оформление заказа работают на живом API бэка: мок-хранилище
`cartStore` с сид-товаром и localStorage-заказами удалено. Корзина гостя определяется
`X-Device-Id` (постоянный id устройства в localStorage), город влияет только на цены и уходит
слагом в каждом запросе. С 24.11.2026 у корзины появился владелец-аккаунт: маршруты
используют `OptionalSanctumAuth`, с Bearer-токеном бэк берёт корзину аккаунта, а вход
и регистрация сливают гостевую корзину с ней. Оформление двухшаговое, как запись
на шиномонтаж: «Оформить заказ» высылает SMS-код, заказ создаётся только после ввода кода;
на шаге кода сервер получает только телефон, а состав берёт из текущей корзины при
подтверждении. Черновик формы и снимок созданного заказа живут в `sessionStorage`; публичного
чтения заказа гостя нет.

## Корзина

- `GET /api/cart?city=`, `POST /api/cart/items`, `PATCH|DELETE /api/cart/items/{item}` — все
  возвращают корзину целиком в `{data}`; мутации кладут ответ в кеш React Query
  (`queryKeys.cart.items(city)`), оптимистичных обновлений нет.
- Адаптер `toCartView` разводит `id` строки корзины (PATCH/DELETE) и `itemable_id` товара
  (кнопки «Купить»); `unit_price`/`total` могут быть `null` — цены города нет, позиция
  недоступна; картинки и артикула в ответе нет, поэтому картинка — общая заглушка
  `/assets/img/wheel-product.png`, «Код товара» не выводится.
- `itemable_type` — только `tire`/`wheel`; категория витрины (`tires`/`wheels`) переводится
  чистой `toItemableType`, неизвестная — отказ.
- Счётчик в шапке (`CartBadge`) сам прогревает кеш корзины; количество — сумма `quantity`.
- **Владелец корзины (с 24.11.2026):** `/api/cart*` и `/api/checkout*` — под
  `OptionalSanctumAuth`. С `Authorization: Bearer` бэк отдаёт корзину аккаунта, без токена —
  гостевую по `X-Device-Id`. Вход и регистрация передают `X-Device-Id`: бэк сливает гостевую
  корзину с корзиной аккаунта и удаляет гостевую. Поэтому фронт шлёт `Authorization` во всех
  запросах корзины и оформления и инвалидирует кэш корзины после входа/выхода — иначе видна
  пустая гостевая корзина, а заказы не привязываются к ЛК. Детали — [account-auth-live-api](account-auth-live-api.md).

## Оформление

- `GET /api/reference/checkout` — способы получения/оплаты с готовыми подписями и флагами
  `requires_pickup_point`/`requires_address`, `code_ttl_min`; читается на сервере. Пустой
  список оплаты — оформление невозможно, кнопка скрыта.
- `GET /api/reference/delivery-points?city=` — точки города; пустой список — самовывоз
  недоступен. Одна точка выбирается автоматически; выбор пропавшей из списка точки сбрасывается.
- Адрес курьера — структура `{city, street, house, apartment?, comment?}`; город по умолчанию —
  город сайта из шапки, поле остаётся правимым.
- Согласия (`offer_accepted`, `privacy_accepted`) отправляются `true`; текст согласия — строка
  фронта (в справочнике его нет).
- Черновик (`checkout-draft`) хранит данные формы, `city`, `idempotencyKey`, `codeIssuedAt`,
  `codeRetryAfter`; ключ генерируется при первом «Оформить заказ» и повторяется на обоих шагах.
  `POST /api/checkout/code` (телефон) → `retry_after` длительности кулдауна; 429 даёт остаток
  в `retry_after`, таймер кнопки считается от него.
- `POST /api/checkout` с черновиком и кодом: 201 — заказ, повтор с тем же ключом — 200 с тем же
  заказом. Бэк сам очищает корзину; кеш корзины инвалидируется.

## Отказы

Разделение — по машинному коду `checkout.*`, не по тексту. Неверный/истёкший/использованный код
остаются на шаге кода (цифры очищаются); пустая корзина и недоступная позиция уводят в корзину;
неверная точка, занятый email и неверный телефон — к форме. Кулдаун — 429 с `retry_after`.
Ошибка валидации без машинного кода сводится к общей формулировке: технические ключи
(`validation.required`) на экран не попадают.

## Страницы и снимок

- `/checkout` → `/checkout/code` (без черновика — редирект на `/checkout`) → `/order/[id]`.
- Страница успеха строится только из снимка ответа в `sessionStorage` (`checkout-order-snapshot`):
  суммы и позиции — сервера, подписи доставки/оплаты — из справочника, который видел
  пользователь; машинный статус не переводится ярлыком. Чужой браузер/вкладка — «заказ не найден».
- `/order-status` — статичная подсказка; мок-поиск по номеру удалён: публичного чтения заказа
  гостя нет, поиск появится с личным кабинетом.

## Общие части

У оформления появилась вторая копия механик записи, они вынесены в `shared/`: OTP-поле
(`shared/ui/OtpCodeInput.tsx`, `shared/lib/otp.ts`), алерт (`shared/ui/Alert.tsx`), кулдаун
(`shared/lib/countdown.ts`), фабрика sessionStorage-сторов (`shared/lib/storageStore.ts`).
Запись на шиномонтаж переведена на них без изменения поведения.
