# Конфиг-грамматика URL каталога (ADR 0002)

> Sources: ADR 0002, 2026-08-07; обновление 2026-08-21 (префиксные размеры, 404)
> Raw: [ADR 0002](../../raw/project/2026-08-19-adr-0002-catalog-url-config.md); [Префиксные размеры w/p](../../raw/project/2026-08-21-filter-url-wp-prefix.md)

## Overview

URL-грамматика каталога (сегменты + query) описывается конфигом `CatalogUrlConfig` + обобщёнными `parseUrl`/`buildUrl` в `shared/lib/parseParams.ts`. Шины и диски — данные (`TIRES_CONFIG`/`WHEELS_CONFIG`), а не копии каркаса.

## Решение

Конфиг: `segmentParsers`, `queryParsers`, `segmentOrder`, `extraQueryFields`. Старые функции остались обёртками — потребители не менялись. Новая категория (мотошины) = новый конфиг без копирования каркаса.

### С 21.08.2026: префиксные размеры шин

Каноничный порядок сегментов шин — `season/brand/w/p/r`: `w185` → `width=185`, `p60` → `profile=60`, `r15`/`r13c` — диаметр (как было). Позиционная пара чисел удалена: профиль без ширины и любое подмножество размеров выразимы без потерь при round-trip (`/catalog/tires/summer/michelin/w185/p60/r15`, `/p60/r15` и т.д.).

Семантика сезон/бренд строгая: сезон — только первый сегмент и без бренда; бренд — первая строка без размерных префиксов и чисел. Сегмент, не распознанный ни одним парсером (голое число, дубль бренда/сезона, строка вне каноничного порядка), — `InvalidCatalogUrlError` → страница отдаёт 404 (`parseCatalogParamsOr404` → `notFound()` в page и generateMetadata).

Query-каналы (auto-вкладка): width/profile — префиксные (`?width=w185`); листинг-query к бэку — числа (`width[]=185`).

## Почему

Rule of Three допускал оставить две пары функций — обобщили на второй копии (каркас идентичен ~70%, третья категория почти наверняка появится). Цена: уровень абстракции при двух реализациях; порядок query-параметров в URL может отличаться (на парсинг не влияет).

Для префиксов рассматривали плейсхолдер «-» в позиционной грамматике (хрупкость позиций, некрасивые URL) и перенос всех размеров в query (теряет SEO-сегменты в пути) — отвергнуты. Цена: старые URL с голыми числами в пути → 404; обратная совместимость сознательно не нужна (проект в разработке).

## Последствия

Семантики зафиксированы в одном месте; мусор в URL — 404, а не тихая порча фильтра. У дисков ширина осталась числом (`6.5`), но строгий `parseUrl` применяется и к ним: нераспознанный сегмент — тоже 404. Пересмотрим: при мультивыборе размеров (бэк принимает `width[]` массивами) сегменты не выражают массивы — формат переедет в query, грамматика упростится, а не сломается. `parseParams.ts` покрыт unit-тестами (Vitest, 48 зелёных).
