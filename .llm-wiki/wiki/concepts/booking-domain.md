# Домен booking (шиномонтаж): макет и правила записи

> Sources: Перенос мокапа шиномонтажа в .template, 2026-09-12
> Raw: [2026-09-12-booking-domain-port](../../raw/project/2026-09-12-booking-domain-port.md)

## Overview

Онлайн-запись на шиномонтаж пришла в проект из соседнего макета tireslot и живёт пока только
как эталон вёрстки — 11 страниц в `.template/booking/`. React-роутов `/booking/*` нет.
Каркас страниц проектный (шапка, футер, крошки, полоса акций), содержимое — 1-в-1 из исходника.

## Поток записи

Четыре шага со степпером, плюс два состояния отказа и раздел «Мои записи»:

| Шаг | Страница | Что на странице |
|-----|----------|-----------------|
| 1 | `booking/index.html` | Календарь на месяц (прошедшие, выходные, выбранный) и чипы слотов времени |
| 2 | `booking/services.html` | Готовые комплексы, услуги с ценой за колесо, параметры авто (радиус, тип) |
| 3 | `booking/details.html` | Имя, телефон, госномер, согласие на обработку данных |
| 4 | `booking/code.html` | Код из SMS (4 разряда), таймер повторной отправки |
| — | `booking/success.html` | Номер записи, состав, сумма, адрес, телефон мастерской |
| — | `booking/code-expired.html` | Состояние: код устарел, запись не создана |
| — | `booking/unavailable.html` | Состояние: слот закрыли, запись не создана |
| — | `booking/my/*` | Вход по телефону → код из SMS → список записей (статусы, отмена) → отмена |

На каждом шаге справа — блок «Ваша запись» с датой, временем, составом услуг и итогом.

## Правила продукта, закодированные в макете

- Цена в прайсе — **за 1 колесо**; итог зависит от радиуса и типа автомобиля
  (легковая / кроссовер / внедорожник), количество задаётся счётчиком.
- Записаться можно не позднее чем **за 1 час** до начала и **в пределах 30 дней**.
- **Слот не удерживается**: запись создаётся только после ввода кода из SMS.
- Код из SMS действует **15 минут**, повторная отправка — по таймеру.
- **Отмена бесплатна**, пока до начала больше 2 часов; ближе — только по телефону.
- Код из SMS служит входом в «Мои записи» (регистрация не нужна), пока запись активна.

Эти правила — вход для будущего React-порта и контракта с бэком: серверные ограничения
(слот, дедлайн, срок кода) и расчёт цены на клиенте не дублируются.

## Решения порта

- Шапка и футер — **1-в-1 как на остальных страницах проекта**, новых пунктов нет.
  Вход в «Мои записи» — ссылками: пункт в футере (группа сервисных ссылок), крошки,
  кнопка на экране успеха. Это единственное расхождение каркаса с проектом.
- Страница «Контакты» исходника не переносилась: в проекте уже есть `/service-page/kontakty`.
- Стили домена дописаны в конец `.template/assets/css/style.css` (+1206 строк, пометка 12.09.2026):
  классы `.booking-*`, `.step*`, `.calendar*`, `.time-chip`, `.code-*`, `.service-checkbox`,
  `.param-chip`, `.status-badge`, `.alert`. Адаптации чужого каркаса вырезаны, веса 800 → 700.
- В `src/app/style.css` стили домена переносятся вместе с React-портом, не раньше.
- Страницы домена ссылаются друг на друга (сквозной поток) — в отличие от страниц витрины.

## Проверки

`verify.mjs` и `check-all.mjs` расширены 11 страницами; в `check-all.mjs` добавлена проверка
статуса ответа и блок проверки внутренних ссылок. Инварианты каркаса: шапка совпадает с
`cart/index.html` побайтово, футер отличается ровно одним пунктом «Мои записи», на каждой
странице ровно один активный шаг степпера. Проверкам нужен `playwright` — в `devDependencies`
проекта его нет (запускались временной установкой).
