# Домен booking (шиномонтаж): поток записи и API

> Sources: Перенос мокапа шиномонтажа в .template, 2026-09-12; React-порт записи на живой API, 2026-09-30
> Raw: [2026-09-12-booking-domain-port](../../raw/project/2026-09-12-booking-domain-port.md); [2026-09-30-booking-react-port](../../raw/project/2026-09-30-booking-react-port.md)

## Overview

Онлайн-запись на шиномонтаж пришла в проект из соседнего макета tireslot (11 страниц
в `.template/booking/`) и с 30.09.2026 работает как React-поток на живом API бэка: пять роутов
`/booking/*`, домен `src/features/booking/`, вход — пункт «Шиномонтаж» в шапке. Раздел
«Мои записи» (`my/*`) остаётся макетом: публичного API для него нет.

## Поток записи

| Шаг | Роут | Что на странице |
|-----|------|-----------------|
| 1 | `/booking` | Календарь на месяц (прошедшие, выходные, свободные, выбранный) и чипы часов дня |
| 2 | `/booking/services` | Готовые комплексы, услуги с ценой за колесо, параметры авто (радиус, тип) |
| 3 | `/booking/details` | Имя, телефон, госномер, согласие на обработку данных; здесь выдаётся код |
| 4 | `/booking/code` | Код из SMS (4 разряда), таймер повторной отправки; здесь же два состояния отказа |
| — | `/booking/success` | Номер записи, состав, сумма, адрес, телефон мастерской |

На каждом шаге справа — блок «Ваша запись» (дата, время, состав, итог, кнопка перехода).
Состояния «код устарел» и «время занято» — состояния шага 4, а не отдельные адреса.

## Правила продукта

- Цена в прайсе — **за 1 колесо**; итог зависит от радиуса и типа автомобиля, количество задаётся
  счётчиком (границы проверяет бэк).
- **Пара радиус+тип обязательна**: без неё подтверждение бэка не проходит (валидация
  `required_with`), поэтому шаг 2 не пропускает дальше, пока пара не выбрана; до выбора обеих
  цен показываются базовые (`base_price`), после — `unit_price`.
- Записаться можно не позднее чем за **1 час** до начала и в пределах горизонта (60 дней);
  срок кода, лид-тайм и количество по умолчанию приходят из `GET /api/reference/booking` —
  это параметры бэка, не константы фронта.
- **Слот не удерживается**: запись создаётся только после ввода кода из SMS.
- **Отмена бесплатна**, пока до начала больше 2 часов; ближе — только по телефону.

## Контракт API (сверен с кодом бэка)

| Шаг | Эндпоинт | Ответ |
|-----|----------|-------|
| Календарь | `GET /api/booking/slots?date_from&date_to` | `{data:{days:{"Y-m-d":bool}}}` — прошлое и за горизонтом тоже `false` |
| Часы дня | `GET /api/booking/slots/{date}` | `{data:{slots:[{hour,is_closed}]}}` |
| Услуги | `GET /api/booking/catalog?radius&car_type` | `{data:{services,complexes,rules}}` — `unit_price` только с парой параметров |
| Код | `POST /api/booking/code {phone}` | `{data:{retry_after}}` — длительность кулдауна, не остаток |
| Запись | `POST /api/booking/confirm` | 201 `{data:{number,…,total_price,items}}`; 200 — повторная отправка кода |
| Справочник | `GET /api/reference/booking` | адрес и телефон мастерской, срок кода, лид-тайм, горизонт, количество |

Ловушки, которые иначе ломают цену молча: `quantities` — **объект с ключом `service_id`**
(массивом бэк подставит количество 1 каждой услуге); `plate` и `quantities` обязаны быть в теле
всегда (пропуск ключа → 500); каталог принимает параметры **только парой** (один параметр → 422).

## Отказы и их различение

Ошибки — доменные (`DomainException` → `{message, code}`); коды `BookingErrorCode` (`booking.*`,
ADR 0027 бэка). Разделение состояний — **по машинному коду, не по тексту**: два отказа шага 4
приходят одним статусом 409 с разным текстом, а правка формулировки молча сломала бы экран.
Ответ без машинного кода (валидация формы) сводится к общей формулировке — технические ключи
вроде `validation.required` на экран не попадают. Действие зависит от состояния: «время занято»
уводит на выбор времени, «код истёк/не найден» — на повторную выдачу кода.

## Решения порта

- **Черновик записи — в `sessionStorage`**, в URL только шаг (ADR 0005): имя и телефон не должны
  попадать в историю браузера и заголовок `Referer`. Прямой заход на шаги 2–4 без времени уводит
  на шаг 1; смена времени сбрасывает выданный код.
- **Экран успеха — отдельный роут со снимком** ответа в `sessionStorage`; черновик при успехе
  очищается. Прецедент — `/order/[id]`.
- **Точка входа — пункт «Шиномонтаж» в шапке** (данные из `GET /api/service_pages`); тот же пункт
  добавлен в шапку 31 файла `.template/*`, иначе макет перестал бы быть эталоном вёрстки.
- **Деньги:** цены идут в копейках до отображения; `shared/lib/money.ts` — `formatMoney` (копейки)
  и обёртка `formatPrice` (рубли); восемь копий `formatPrice` в проекте сведены на импорт.
- **Стили домена переехали в `src/app/style.css`** (1005 строк, пометка 30.09.2026); стили
  раздела «Мои записи» (`my/*`) и мёртвый `.map-placeholder` остались в макете до порта раздела.

## Что не сделано

Раздел «Мои записи» (`my/*`, 4 страницы макета) — публичный API его не покрывает: нет ни списка
записей, ни отмены, ни входа по коду. Отдельная фаза, когда API появится.

## Проверки

16 юнит-тестов в пяти файлах (`tests/unit/booking*.test.ts`; красный прогон до реализации) + полный
набор 73 теста. Сквозной прогон в браузере на живом API: записи `TS-000040`, `TS-000041`, экран
отказа, мобильное разрешение. Макет: `check-all.mjs` — 0 переполнений и 0 битых ссылок. Состояние
«код устарел» живьём не воспроизводилось (срок кода 15 минут) — закрыто юнит-тестами.
