# Фоллбэк ошибок бэка: самостоятельная страница ошибки

> Sources: План backend-error-fallback и прогоны на прод-сборке, 2026-10-16
> Raw: [global-error-page](../../raw/project/2026-10-16-global-error-page.md)

## Overview

Любое необработанное исключение — главный случай: 5xx или недоступность Laravel-бэка
на живом фетче — отдаёт HTTP 500 и **самодостаточную страницу ошибки**: без шапки и
подвала, без единого обращения к API, с кнопками «Обновить» (полная перезагрузка) и
«На главную». Механика — единственная верхняя React-граница
`src/app/global-error.tsx`, намеренно заменяющая root layout целиком. Решение
согласовано с требованием: страница ошибки не зависит от API вообще — «если нет
ответа от бэка, это уже не сайт»; частичная деградация не нужна.

## Кто зависит от живого бэка

- `getGeo()` (`GET /api/reference/city`) ждут 6 серверных страниц: каталог шин
  (params + auto), каталог дисков (params + auto), модель шины, типоразмер — одна 500
  по справочнику городов роняет все шесть.
- Каталог шин дополнительно: `getCatalogFilters()` (`/api/reference/filter/tire`),
  `getCatalogProducts()` (`/api/catalog/tires`), в т.ч. `generateMetadata`.
- Запись на шиномонтаж — клиентские запросы (React Query): доменные отказы разобраны
  `mapBookingError`; общий 500 даёт тихие пустые списки (долг, вне области).
- Клиентский `useGeo` в шапке при недоступном бэке — пустой город, без падения
  (долг, вне области).

## Почему global-error, а не error.tsx

`error.tsx` рисуется **внутри** root layout, а обвязка тянет живой `useGeo` — страница
ошибки тогда сама ходила бы в API и показывала пустой город. `global-error` заменяет
layout целиком: свои `<html lang="ru">/<body>`, собственный импорт `style.css`
(глобальные стили сюда не наследуются), `<title>` React-элементом вместо metadata.
Он же ловит ошибки самого root layout — вторая граница не нужна.

## Поведение

- Прямой заход и клиентский переход по `<Link>` — одинаковая страница ошибки; «На
  главную» — обычная ссылка `<a href="/">` (полная загрузка; осознанное отключение
  правила `@next/next/no-html-link-for-pages`), «Обновить» — `window.location.reload()`
  (`unstable_retry` отклонён: помечен unstable, «мягкий» повторный рендер не нужен).
- Мок-страницы без живых фетчей (главная, статьи, корзина, checkout…) при мёртвом
  бэке работают как обычно — ошибка туда не протекает.
- Мок-страницы с живым `getGeo` (модель, типоразмер, диски) при 500 города тоже
  показывают страницу ошибки — единое поведение без точечных смягчений.
- В Next 16.2 500-ответ — оболочка `__next_error__`; страница ошибки отрисовывается
  клиентом (у дефолтной страницы Next то же самое; без JS виден пустой документ).
- Стили `.error-page*` — в конце `src/app/style.css` с пометкой 15.10.2026 (макета нет).

## Вне области

404-страница (`notFound()` даёт дефолт Next), тихие пустые состояния booking, пустой
город в шапке при недоступном гео, `error.tsx` для внутренних границ.
