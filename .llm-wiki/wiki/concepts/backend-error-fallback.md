# Фоллбэк ошибок бэка: страница ошибки — карточка макета в живой обвязке

> Sources: План backend-error-fallback и прогоны на прод-сборке, 2026-10-16; Макет страницы ошибки и его порт в error.tsx, 2026-10-16
> Raw: [global-error-page](../../raw/project/2026-10-16-global-error-page.md); [error-page-mockup](../../raw/project/2026-10-16-error-page-mockup.md); [error-page-port](../../raw/project/2026-10-16-error-page-port.md)

## Overview

Любое необработанное исключение — главный случай: 5xx или недоступность Laravel-бэка
на живом фетче — отдаёт HTTP 500 и страницу ошибки: карточку «Сервис временно
недоступен» из макета внутри **живой обвязки** (граница сегмента `src/app/error.tsx`,
16.10.2026). Нижний слой — `global-error.tsx`: самодостаточная страница без обвязки
(«Обновить», «На главную»), срабатывает при падении самого root layout. Решение
эволюционировало: сначала самостоятельная страница (требование «не зависеть от API»),
после появления макета с шапкой выбран вариант с живой обвязкой — цена: пустой город
в шапке.

## Кто зависит от живого бэка

- `getGeo()` (`GET /api/reference/city`) ждут 6 серверных страниц: каталог шин
  (params + auto), каталог дисков (params + auto), модель шины, типоразмер — одна 500
  по справочнику городов роняет все шесть.
- Каталог шин дополнительно: `getCatalogFilters()` (`/api/reference/filter/tire`),
  `getCatalogProducts()` (`/api/catalog/tires`), в т.ч. `generateMetadata`.
- Запись на шиномонтаж — клиентские запросы (React Query): доменные отказы разобраны
  `mapBookingError`; общий 500 даёт тихие пустые списки (долг, вне области).
- Клиентский `useGeo` в шапке при недоступном бэке — пустой город без падения.

## Слои

- `src/app/error.tsx` (граница сегмента) — карточка макета 1-в-1
  (`.error-section → .error-card`: `error.svg`, заголовок «Сервис временно недоступен»,
  два абзаца) + кнопка «Обновить» (`window.location.reload()`); `console.error(error)`
  (digest — для логов). Рисуется внутри root layout: шапка/подвал/меню — настоящие
  компоненты, не копии (моки/localStorage работают). Единственная видимая потеря при
  мёртвом бэке — пустой город: остров `CityBadge` сходит в API и не получает ответа
  (при клиентской навигации может остаться из кэша).
- `src/app/global-error.tsx` (нижний слой) — заменяет root layout целиком: свои
  `<html lang="ru">/<body>`, собственный импорт `style.css` (глобальные стили сюда не
  наследуются), `<title>` React-элементом, логотип, «Обновить» и «На главную»
  (обычная ссылка — осознанное отключение `@next/next/no-html-link-for-pages`).
- Стили: `.error-section/.error-card/.error-picture/.error-title/.error-text/.error-button`
  — в конце `src/app/style.css` с пометкой 16.10.2026 (перенос из макета, правило
  ui-porting 9); у нижнего слоя — `.error-page*` (15.10.2026). Ассет —
  `public/assets/img/error.svg` (в мокапе остаётся).

## Поведение (прогоны на прод-сборке, заглушка 500)

- 500-ответ и у `error.tsx`, и у `global-error` — оболочка `__next_error__`; карточку и
  обвязку рисует клиент (без JS пусто — у дефолтной страницы Next то же).
- Сценарии `error.tsx`: прямой заход — карточка в живой обвязке (шапка/подвал, город
  пустой); «Обновить» после оживления бэка → 12 карточек и город вернулся; клиентский
  переход из меню — карточка, обвязка жива (логотип ведёт на главную); мок-страницы без
  живых фетчей живы; мок-страница с живым гео → карточка.
- Мок-страницы с живым `getGeo` (модель, типоразмер, диски) при 500 города тоже
  показывают карточку — единое поведение без точечных смягчений.

## Вне области

404-страница (`notFound()` даёт дефолт Next), тихие пустые состояния booking, пустой
город при недоступном гео (согласованная потеря).
