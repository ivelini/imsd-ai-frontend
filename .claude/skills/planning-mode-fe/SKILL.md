# Planning mode — Next.js (template, aalyans.ru)

Локальная версия: глобальный `planning-mode` заточен под Laravel (`Action`, `Contracts`,
`Preconditions`, миграции). Здесь — планирование в этом репозитории: Next.js 16 App Router,
React 19, TypeScript.

**Главное правило: ничего не додумывать.** Каждое утверждение плана опирается на код,
документ или явный ответ пользователя. Нет источника — это пробел, и он закрывается вопросом
(Шаг 2), а не догадкой.

## Профиль проекта

- Слои: `src/app/` — роутинг и композиция страниц; `src/features/<домен>/` — домен
  (`components`, `api`, `types`); `src/shared/` — ядро (`api`, `ui`, `layout`, `lib`, `types`);
  `src/data/` — моки ответов бэка; `src/stores/` — Zustand только UI; `.template/` — HTML-макет
  (эталон вёрстки, в рантайм не входит).
- Правила: `CLAUDE.md`; `.claude/rules/frontend-architecture.md`, `ui-porting.md`,
  `api-contract.md`, `base.md`; глобальные `~/.claude/rules/plans.md`, `simplicity.md`,
  `coding-style.md` — из последнего брать принципы, а Laravel-механику (`Action`,
  `Preconditions`, `DTO`, `Resource`, `Eloquent`, миграции) не переносить.
- Источник API: `../backend/documentations/scramble/public-api.json` — единственная истина;
  моки `src/data/` контрактом не считаются.
- Документы: `documentations/adr/` (+ индекс в `CLAUDE.md`), `.llm-wiki/wiki/index.md`,
  `documentations/operations.md`.
- Планы: `.claude/plans/`.
- Команды: `npm test` (Vitest, `tests/unit/`), `npm run lint`, `npx tsc --noEmit`.
  `npm run build` — только при остановленном dev-контейнере (общий `.next` повреждается);
  dev — `make up`, порт 30034.
- Next 16 — не по памяти: перед предложением кода на новых API читать
  `node_modules/next/dist/docs/` (правило `AGENTS.md`).
- Разведка кода: MCP `codegraph_explore`; `graphify query "<вопрос>"` — только если в проекте
  есть `graphify-out/graph.json`.

## Шаг 1. Архитектурная сверка (до задач)

Разведка по коду, который план затронет: `codegraph_explore` (нет — `Read`/`Grep`). План,
написанный по памяти, а не по текущим связям, не согласуется.

Проверь и покажи:

- **Слой.** Что меняем: роут (`src/app/.../page.tsx`), доменный компонент/хук
  (`src/features/<домен>/`), ядро (`src/shared/`), мок (`src/data/` — только если API нет),
  UI-состояние (`src/stores/`). Бизнес-логика в компоненте роутинга — сигнал вынести в домен.
- **Server/client.** Каждый новый компонент — серверный по умолчанию; `"use client"` — только
  под интерактив, браузерные API или мутации. Клиентские острова — минимальные.
- **Данные.** Доступ только через `src/shared/api/`; компоненты не импортируют `@/data/*`.
  DTO бэка (snake_case) → тип фронта в `features/*/types` или `shared/types`; адаптер —
  чистая функция.
- **Состояние.** Фильтры и пагинация — в URL; клиентские данные — React Query; Zustand —
  только UI (город, попапы, меню). Новый Zustand-стор под данные — нарушение.
- **Границы доменов.** Домен не импортирует компоненты другого домена; разрешены типы,
  `shared/types`, `shared/ui`, `shared/lib`.
- **API-контракт.** Данные для отображения — готовые `{label, value}` и строки от бэка;
  `value` совпадает с сегментом URL. Фронт-словарь для показа — недоработка бэка, а не решение.
- **Роутинг.** Адрес и сегменты — по «Схеме роутов» в `CLAUDE.md`; новые маршруты и редиректы —
  отдельное решение в плане.
- **Вёрстка.** Разметка 1-в-1 из `.template/`, семантические теги без смены классов, BEM,
  без Tailwind; стили — в `src/app/style.css`, новые блоки — в конце с пометкой даты.
- **Тестируемость.** Логика, которую нельзя проверить unit-тестом без браузера, выносится
  в чистую функцию/адаптер (`shared/ui/badgeView.ts` — образец).
- **Переиспользование.** Правило двух: вторая копия правила/формата — общий источник в бюджет.
- **Паттерн.** Нужен — фраза гейта «вторая копия — X, изолирует правку Y»; нет фразы — паттерн
  не вводится (`simplicity.md`). Симптом паттерна — `/patterns-mode`.

Расхождение с правилами или ADR — назвать и предложить: обновить документ, ADR или отступить.

## Шаг 2. Вопросы: закрыть пробелы до плана

1. **Сначала ищи ответ сам** — в коде, конфиге, документах, планах и отчётах. Вопрос задавай,
   только если ответа нет или ответ меняет продукт.
2. **Один вопрос — одно сообщение**, по `os-ask-simple`: простыми словами, варианты,
   рекомендация, цена. Если оба ответа ведут к одной работе — это не развилка.
3. **Спрашивай до конца.** Пока неопределённость влияет на данные, поведение, экран или тест,
   план не пишется. Пройди по разделам будущего плана: сущности, поля, состояния, ошибки,
   пустые данные, права, UI, тесты.
4. **Фиксируй ответ сразу:** таблица «вопрос → ответ → следствие в плане», ответ дословно.
5. **Перед показом плана проверь полноту:** у каждого утверждения есть источник;
   конвенциональный дефолт помечен «дефолт, не подтверждён».
6. **К моменту согласования «Открытые вопросы» пусты** — иначе план не показывается.

## Шаг 3. План в `.claude/plans/<название>.md`

Обязательные разделы (формат — `plans.md`):

1. Решения, согласованные в обсуждении: вопрос → ответ → следствие в плане.
2. Цель и ожидаемый результат.
3. Задачи с контрактом шага: шаг → файл::функция/компонент → вход → выход. Функция — ≤ 3
   параметров; больше — DTO/объект в бюджете. Пропсы React-компонента — один объект.
4. Новые сущности: путь → зачем; для паттерна — вторая копия/ось изменения; переиспользуем: …;
   «Не делаем» — явным списком.
5. Сначала минимальный вариант: простейший рабочий и отклонённый тяжёлый с ценой.
6. STOP-условие и бюджет диффа: файлы/строки на шаг.
7. Тест-лист.
8. Схема вызовов реальными файлами и функциями, сверху вниз (ASCII).
9. Открытые вопросы — пусто.
10. После согласования — строка `**Согласовано:** <дата>`.

### Тест-лист в этом проекте

- Тесты — Vitest, `tests/unit/*.test.ts`, окружение `node`; проверяются чистые функции,
  адаптеры, view-model. React Testing Library не установлена: компонентный/DOM-тест требует
  новой зависимости — это STOP и отдельное решение.
- Формат строки: поведение (правило или граница) / вход с конкретными значениями / ожидание /
  имя `test_...`.
- Тест, который не сводится к «вход → выход», означает, что логика не отделена: в плане
  появляется чистая функция, тест пишется на неё.
- Файл называется по модулю: `tests/unit/<адаптер>.test.ts`.
- Тест-лист — собственность пользователя: AI предлагает, пользователь правит. Без явного
  подтверждения реализация не начинается.

### Схема вызовов

ASCII, сверху вниз, только участники механики: триггер (роут, событие, клик) → серверный или
клиентский компонент → `shared/api` → внешний API → тип/состояние → рендер. Участники —
реальные файлы проекта, стрелки — реальные вызовы. Mermaid в чат не выводить.
