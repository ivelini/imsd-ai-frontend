# Review — Next.js (template, aalyans.ru)

Третий шаг цикла: `/planning-mode-fe` (план) → `/coder-mode-fe` (реализация) → `/review-fe`
(сверка и рефакторинг). Поведение не меняется, новых сущностей не появляется.

## Шаг 0. Гейт

- Есть незакоммиченные изменения кода: `src/`, `tests/`, `package.json`, `next.config.ts`,
  `eslint.config.mjs`, `tsconfig.json`, `vitest.config.ts`, `server.mjs`, `Makefile`, `docker/`.
  md, доки и `.claude/` кодом не считаются.
- Ревью этого же набора уже выполнено в этом ходе — сообщи «Ревью выполнено» и выйди.
- План в `.claude/plans/`: если набор ему соответствует, план читается как контракт. Планов
  несколько — спроси, какой; не угадывай.
- Источники правил: `CLAUDE.md`, `.claude/rules/*.md`; глобальные `plans.md`, `simplicity.md`,
  `coding-style.md` (принципы; Laravel-механику не переносить).

## Шаг 1. Контекст

- `git status --porcelain`, `git diff`, untracked — читать полностью.
- Суть набора — 3–5 строк.
- Источники: план, `CLAUDE.md`, `.claude/rules/frontend-architecture.md`, `ui-porting.md`,
  `api-contract.md`, `base.md`, `git.md`, `wiki-sync.md`; ADR/wiki по теме; Scramble-экспорт,
  если меняется API.

## Шаг 2. Агент

1. `.claude/agents/architecture-reviewer.md` есть — Agent tool, `subagent_type:
   architecture-reviewer`: суть набора, список файлов, путь к плану, ссылки на источники.
   Дождись отчёта, не пересказывай заранее.
2. Агента нет или он не зарегистрирован в сессии — проверь сам по чек-листу Шага 3.
3. Субагентов в клиенте нет — проверь сам.

## Шаг 3. Что проверяется (в этом порядке)

1. **План vs факт:** сущности только из бюджета, контракты шагов соблюдены, тест-лист покрыт,
   отклонения названы.
2. **Слои и границы:** `src/app/` — роутинг и композиция, `src/features/<домен>/` — домен,
   `src/shared/` — ядро, `src/data/` — моки, `src/stores/` — только UI. Домены не импортируют
   компоненты друг друга; `shared/` — только для двух и более потребителей.
3. **Server/client:** серверный по умолчанию; `"use client"` только под интерактив, браузерные
   API или мутации; бизнес-логики в компонентах роутинга нет.
4. **Данные:** только через `src/shared/api/`; компоненты не импортируют `@/data/*`; DTO бэка →
   адаптер → тип фронта; нет `fetch` в компонентах; API по Scramble, не по мокам.
5. **Состояние:** фильтры и пагинация — URL; клиентские данные — React Query; Zustand — только
   UI; нет `useEffect` для запросов и клиентской фильтрации.
6. **API-контракт:** `{label, value}` и строки для показа — от бэка; `value` = сегмент URL;
   фронт не строит словари и маппинги.
7. **Вёрстка:** разметка 1-в-1 из `.template/`; семантические теги; BEM; без Tailwind; `<img>`
   по правилу ui-porting; стили — `src/app/style.css`, новые блоки в конце с пометкой даты.
8. **Простота:** правило двух; нет абстракций «на будущее», интерфейсов с одной реализацией,
   слоёв-делегатов, мёртвого кода, дублей правил; нет Laravel-сущностей (`Action`,
   `Preconditions`, `DTO`, `Resource`) — здесь их место занимают компоненты, хуки и адаптеры.
9. **Тесты:** Vitest, `tests/unit/*.test.ts`, чистая функция, имя `test_...`, покрытие
   тест-листа. Компонентных тестов нет — React Testing Library не установлена.
10. **Типы и стиль:** TypeScript strict, `@/*`, DTO не выдуманы, комментарии «почему», а не «что».

## Шаг 4. Исправления — только рефакторинг

- Менять только нарушения; поведение не менять; новых сущностей не добавлять.
- Сначала убедись, что тесты зелёные; после правок прогони снова.
- STOP, если исправление требует новой сущности, зависимости, настройки, маршрута или
  API-контракта; если план расходится с кодом; если нарушение в файлах вне набора —
  зафиксировать, не чинить.
- Если правки меняют бизнес-логику или функционал — отдельной строкой в отчёте: «нужно
  обновить wiki» (`.claude/rules/wiki-sync.md`).

## Шаг 5. Прогоны и отчёт

- `npm test`, `npm run lint`, `npx tsc --noEmit`. Build и dev-сервер не запускать при живом
  dev-контейнере (общий `.next`).
- Если в проекте есть `graphify-out/graph.json` — после правок `graphify update .`.
- Прогоны записать в «Прогоны» плана, если план есть.
- Отчёт: таблица нарушений (файл:строка, правило, исправлено/нет), план vs факт, прогоны
  до/после, что осталось и почему.
- Не коммитить; пуш и выкладка — за пользователем.
