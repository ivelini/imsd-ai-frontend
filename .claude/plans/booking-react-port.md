# React-порт публичной части записи на шиномонтаж (booking) на живом API

**Дата:** 2026-09-28 · **Статус:** согласован (итерация 1), ждёт выполнения ТЗ бэка

## Цель

Макет-эталон `.template/booking/` (11 страниц, перенесён 12.09.2026) превратить в рабочий
React-поток на живом API бэка: 5 роутов `/booking/*`, домен `src/features/booking/`,
стили домена — в `src/app/style.css`. Данные — из `GET /booking/slots`,
`GET /booking/slots/{date}`, `GET /booking/catalog`, `POST /booking/code`,
`POST /booking/confirm` и нового `GET /reference/booking` (источник истины —
`../backend/documentations/scramble/public-api.json`, сверен с кодом бэка).

## Что входит / не входит

**Входит:** шаги 1–4 потока (время → услуги → данные → код), экран успеха, два состояния
отказа (код устарел / время занято), точка входа в шапке.

**Не входит:** раздел «Мои записи» (`my/*`, 4 страницы) — публичный API его не покрывает
вообще: нет ни списка записей, ни отмены, ни входа по коду. Отдельная фаза, когда появится API.

## Контракт API (сверено с кодом бэка, не только со Scramble)

| Шаг | Эндпоинт | Ответ |
|---|---|---|
| Календарь | `GET /api/booking/slots?date_from&date_to` | `{data:{days:{"Y-m-d":bool}}}` — bool = есть открытый слот; прошлое и за горизонтом тоже `false` |
| Часы дня | `GET /api/booking/slots/{date}` | `{data:{slots:[{hour,is_closed}]}}` — только существующие часы, от первого доступного; `is_closed` → чип «занято» |
| Услуги | `GET /api/booking/catalog?radius&car_type` | `{data:{services:[{id,name,base_price,has_rules,unit_price?}], complexes:[{id,name,service_ids:[int]}], rules:{radius:[{value,label}],car_type:[{value,label}]}}}` |
| Код | `POST /api/booking/code {phone}` | `{data:{retry_after:int}}` — **конфиг кулдауна (60 с), не остаток**; 429 если рано; 422 невалидный телефон |
| Запись | `POST /api/booking/confirm {...}` | 201 `{data:{id,date,start_time,status,radius,car_type,plate,total_price,user,items}}`; 200 — повторный submit тем же кодом |
| Параметры записи | `GET /api/reference/booking` — **новый**, см. ТЗ бэка | адрес и телефон мастерской, TTL кода, лид-тайм, горизонт, дефолтное количество |

Ошибки — `DomainException` → `{message}` со статусом 409 (по умолчанию) / 422 / 429.
ТЗ бэка добавляет в тело машинный `code` и остаток `retry_after` в 429; до его выполнения
фронт доменные ошибки не различает.

### Неочевидное, что определяет реализацию

1. **`quantities` — объект с ключом `service_id`**, а не позиционный массив (в OpenAPI описан
   как `array of integer` — расхождение). При `[4,4,4]` PHP разложит в `{0:4,1:4}`,
   `PriceCalculator` не найдёт ключ и **молча подставит количество 1** — цена уедет без ошибки.
2. **`quantities` и `plate` обязаны присутствовать в теле всегда.** Валидация их не требует,
   но контроллер читает `$data['quantities']` и `$data['plate']` безусловно — пропуск ключа
   даёт 500 `Undefined array key`. Госномер без значения → `null`.
3. **`GET /booking/catalog?radius&car_type` может вернуть 422.** Если у услуги есть прайс-правила,
   а комбинации (услуга, радиус, тип) нет — `PriceCalculator` бросает исключение прямо при
   сборке каталога. Шаг 2 обязан это пережить, а не падать.
4. `total_price` и `base_price`/`unit_price` — **в копейках**.
5. `unit_price` в каталоге появляется только когда переданы **оба** параметра (радиус и тип).
   Без них — только `base_price`.
6. **Данных для экрана успеха в API нет:** адрес и телефон мастерской лежат в `settings`
   бэка (`shop_address` = «г. Челябинск, Копейское шоссе, 12А», `shop_phone`), но наружу
   не отдаются; номера вида `TS-000123` нет вовсе — только int `id`. Адрес из макета,
   таким образом, **верный** — мастерская и магазин находятся по разным адресам.
7. **Два состояния отказа приходят одним статусом 409** с разным текстом (`Код истёк…` /
   `Слот недоступен…`), 422 смешивает `Код не найден` и `Нет прайс-правила`. Различить их
   можно только по машинному коду — он в ТЗ бэка (п. 2.1).
8. Часы работы мастерской (9:00–19:00), лид-тайм (1 ч), горизонт записи, срок жизни кода
   (15 мин) — в API не отдаются, живут в настройках бэка. Часы работы фронт считает сам
   по слотам дня; остальное — из справочника (п. 2.3 ТЗ бэка). Горизонт на бэке противоречив:
   сидер 60 дней, `SettingKeyEnum::default()` и ФТ §7 — 30.

## Решения

1. **Роуты:** `/booking` (шаг 1), `/booking/services`, `/booking/details`, `/booking/code`,
   `/booking/success` — по образцу макета (`index/services/details/code/success`).
   Состояния «код устарел» и «время занято» — не роуты, а состояния внутри `/booking/code`
   (в макете это тот же экран кода с алертом).
2. **Черновик записи — в `sessionStorage`** (один объект), URL несёт только шаг.
   Причина: имя и телефон нельзя класть в URL (утекут в историю, реферер и логи), а держать
   часть состояния в URL, а часть в хранилище — два источника истины на один черновик.
   Прямой заход на шаги 2–4 с пустым черновиком → редирект на `/booking`.
3. **Экран успеха — отдельный роут со снапшотом** в `sessionStorage`: после 201 (или 200 при
   повторном submit) сохраняем ответ и `router.replace('/booking/success')`. Прецедент в
   проекте — `/order/[id]` (заказ в localStorage). Снапшот пропал → редирект на `/booking`.
4. **Точка входа — пункт «Шиномонтаж» → `/booking` в шапке.** Данные шапки приходят из
   `GET /api/service_pages` (мок `src/data/servicePages.ts`, блок `type: "header"`), поэтому
   правка — одна строка данных, разметка шапки не меняется.
   **Макет `.template/*` (27 страниц) обновляется тем же коммитом** — пункт добавляется в шапку
   скриптом, проверки макета прогоняются заново. Иначе мокап перестанет быть эталоном вёрстки,
   а инвариант `header_matches_project` из прошлой фазы станет ложным.
   `GET /api/service_pages` в бэке пока не реализован (только мок фронта) — когда появится,
   пункт «Шиномонтаж» должен быть в блоке шапки; зафиксировано в §5 ТЗ бэка.
5. **Цены держим в копейках** до отображения (как отдаёт API), форматирование — одна функция
   на проект. Пятая копия `formatPrice` (сейчас в 5 файлах) не создаётся: модуль
   `src/shared/lib/money.ts` с ядром `formatMoney(kopecks)` и обёрткой `formatPrice(rubles)`
   для существующих экранов; пять копий заменяются импортом.
6. **Параметры авто на шаге 2 не предвыбраны.** В макете стоит R16 + кроссовер — это
   произвольная выборка source-макета, а не правило. До выбора обоих параметров список
   показывает `base_price`, а сводка — подсказку «выберите параметры, чтобы увидеть итог»
   (текст подсказки в макете уже такой). Количество услуги по умолчанию — 4 (как в макете);
   границы 1–4 проверяет бэк.
7. **Адрес и телефон мастерской** для экрана успеха — из нового `GET /api/reference/booking`
   (см. ТЗ бэка), источника истины по ним. Значения — из `settings`: «г. Челябинск, Копейское
   шоссе, 12А» и «+7 (351) 70-00-319» (адрес мастерской, не магазина — магазин на
   Свердловском тракте). До появления эндпоинта — мок `src/data/booking.ts` с теми же
   значениями, как имитация ответа бэка.
8. **Кнопка «Моя запись» и примечание о ней убираются с экрана успеха** — раздел не
   портируется в этой фазе, а ссылка в никуда хуже отсутствия ссылки. Вернутся вместе с `my/*`.
9. **Номер записи** — `№ {id}` из ответа бэка. Человекочитаемого номера вида `TS-000123`
   в API нет — выдумывать формат на фронте нельзя. Вынесено решением продукта в §4.1 ТЗ бэка;
   до решения показываем `id`.

## Задачи

7. **Точка входа.** Пункт «Шиномонтаж» в данных шапки (мок) + тот же пункт в шапку 27 страниц

8. **Зелёный прогон** + ручная проверка потока в браузере (сквозной сценарий и оба отказа).

### `tests/unit/bookingCalendar.test.ts` — сетка календаря

**Тест 1**
1. Поведение: прошедший день не кликабелен, даже если бэк вернул по нему `true` — прошлое отсекается по календарю, а не по карте доступности

1. Поведение: дата с `false` в карте — «выходной», а не «свободно»: в макете это разные точки легенды, и обе видны пользователю

## Согласованные уточнения (итерация 1)

1. **Разделение ошибок — по машинному коду от бэка** (согласовано 28.09.2026): бэк добавляет
   поле `code` в ответ `DomainException`. Временно, до правки бэка, фронт не ветвится по тексту —
   соответствующие состояния просто не показываются.
2. **Точка входа — пункт в шапке** (согласовано 28.09.2026), ярлык — «Шиномонтаж».

  ФТ §7 — `30`. До появления справочника фронт не хардкодит ни то, ни другое.
