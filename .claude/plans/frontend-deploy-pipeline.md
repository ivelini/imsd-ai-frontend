## Цель

Пуш в `master` репозитория `ivelini/imsd-ai-frontend` → проверки → сборка → выкладка на
`https://aalyans74.ru` → проверка живости. По образцу бэкенда (`backend/.github/workflows/`),
тот же сервер и тот же SSH-ключ.

и `npm start` = `node server.js`. Панель при перезапуске сама поднимет процесс по сохранённому
cwd — каталог сайта станет ссылкой на релиз (как у бэка), pm2 перечитает его через ссылку.

## Схема

```
┌─ ТРИГГЕР ──────────────────────────────────────────────┐
│  Пуш в master  (или Actions → «Выкладка на прод»)      │
└───────────────────────────┬─────────────────────────────┘
                            ▼
┌─ GITHUB ACTIONS ───────────────────────────────────────┐
│  job checks  →  ci.yml (workflow_call)                 │
│      npm ci → lint → типы → vitest                     │
│  job deploy  (ubuntu-latest, node 24)                  │
│      npm ci → npm run build                            │
│        BACKEND_URL=https://api.aalyans74.ru            │
│        (запекается в rewrites сборки)                  │
│      SSH: ключ из секрета PROD_SSH_KEY                 │
└───────────────────────────┬─────────────────────────────┘
                            │ ssh / rsync
                            ▼
┌─ СЕРВЕР: /var/www/aalyans74_ru/data/www ───────────────┐
│  mkdir releases_front_aalyans74/<дата-время>/          │
│    rsync: код + .next + node_modules? — нет           │
│    npm ci --omit=dev   (node из /usr/lib/ispnodejs)    │
│    cp build/.env.frontend.prod → <релиз>/.env          │
│  aalyans74.ru → ссылка на релиз  (mv -T, атомарно)     │
│  PM2_HOME=…/.pm2 pm2 restart aalyans74.ru              │
│  curl через сокет + публичный https → 200 и заголовок  │
│  чистка старых релизов (KEEP_RELEASES=3)               │
└───────────────────────────┬─────────────────────────────┘
                            ▼
┌─ ПРОД ─────────────────────────────────────────────────┐
│  nginx aalyans74.ru: файлы из каталога сайта,          │
│      остальное → unix:…/nodejs/0.sock                  │
│  server.js (кастомный Next) ← поднят pm2, cwd=релиз    │
│  серверные запросы: apiBase() → BACKEND_URL из .env    │
└────────────────────────────────────────────────────────┘
```

## Изменения в репозитории

1. **`server.js`** (новый, корень) — кастомный сервер Next: `next({ dev: false, dir: __dirname })`,
   слушает `SOCKET` (после `unlink`, права 0660 — как в шаблоне панели), иначе `PORT`
   (локальный запуск). `.env` грузит сам Next при старте.
2. **`package.json`** — `"start": "node server.js"` (панель запускает ровно `npm start`).
3. **`.github/workflows/ci.yml`** — только `workflow_call`: линтер, типы, тесты.
4. **`.github/workflows/deploy.yml`** — `push: master` + `workflow_dispatch`; `concurrency`,
   `timeout-minutes`, проверки → сборка → выкладка → проверка → чистка (структура бэка).
5. **`documentations/operations.md`** (новый) — раскладка на сервере, настройки выкладки,
   разовая подготовка, откат.

   Делает пользователь (в GitHub у агента нет доступа). Статус: ждёт пользователя.
2. На сервере `build/.env.frontend.prod` — сделано 06.10.2026.
3. Заглушка панели переименована в `aalyans74.ru.placeholder-06.10.2026` — сделано 06.10.2026

4. Коммит и пуш — пользователь делает сам; пуш в `master` запускает первый прогон выкладки.

## Прогоны

- Красный/зелёный по проверкам (06.10.2026): до правок — линтер 3 ошибки (`react-hooks/set-state-in-effect`),
  `tsc --noEmit` 3 ошибки; после — `eslint` 0 ошибок (15 прежних предупреждений), `tsc` чисто, `vitest` 73 passed.
- `server.mjs` в копии проекта `/tmp/fe-probe` (общий `.next` не трогался): сборка с `BACKEND_URL` —
  в `routes-manifest.json` адрес `https://api.aalyans74.ru/api/:path*` (rewrites запекаются на сборке);
  `SOCKET=/tmp/fe-probe/probe.sock node server.mjs` → `> Ready on unix:…`, сокет 0660, запрос через сокет
  → 200, `<title>Альянс — шины и диски</title>`, в HTML есть `/_next/static/`; без `SOCKET` (PORT=3007) → 200;
  перезапуск при существующем сокете — ок (unlink сработал). `.env` с `BACKEND_URL` подхватился в рантайме:
  серверный запрос каталога дошёл до живого бэка (ответ 422 от API на `brand=michelin` — в прод-БД бэка
  нет данных, не дефект выкладки).
- Прод-режим зависимостей: `npm ci --omit=dev` (485 МБ) в копии — приложение поднялось на сокет, 200 и тот же заголовок.
- Песочница на сервере (`/tmp/sandbox-deploy`, убрана): защита «каталог сайта — не ссылка» останавливает
  выкладку с понятным сообщением; первый релиз создаёт ссылку, повторный — переключает; чистка оставила
  3 свежих релиза и не тронула посторонний каталог `backup-old`.
- Найден и исправлен дефект: `pm2` в SSH-сессии падает (`/usr/bin/env: node: No such file`) — шаг
  перезапуска теперь экспортирует `PATH` с панельным node. После правки `pm2 describe aalyans74.ru` видит
  приложение (status online, cwd — каталог сайта).

Не проверено (ждёт первого реального прогона): зелёный прогон в Actions, переключение ссылки на
рабочем каталоге, ответ по домену, откат, чистка релизов на проде.

## Риски и что пересмотреть

- Два места, где задан адрес бэка: `BACKEND_URL` в workflow (запекается в сборку) и
  `build/.env.frontend.prod` (серверные запросы). Менять — вместе, отмечено в operations.md.
- Кастомный сервер исключает режим `output: 'standalone'` (док Next) — при переезде на
  хостинг с TCP-портом пересмотреть.
- Перезапуск pm2 даёт паузу ~1–2 с (перезапуск процесса, окна без кода нет).
