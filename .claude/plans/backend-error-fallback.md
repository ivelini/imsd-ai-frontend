# Фоллбэк ошибок бэка: самостоятельная страница ошибки

Статус: реализовано 15.10.2026, прогоны ниже (схема и тест-лист согласованы, итерация 2).

## Цель

При 5xx или недоступности бэка страницы, тянущие живые данные, сейчас падают в
дефолтный экран ошибки Next (в prod — «Application error…»). Показывать свою
страницу ошибки: самодостаточную (ни одного обращения к API, без шапки/подвала),
с кнопками «Обновить» и «На главную». Раз бэк не отвечает — сайт всё равно
нерабочий; частичная деградация не нужна.

## Факты (из кода, 15.10.2026)

- Живые фетчи фронта: `getGeo` → `/reference/city`, `getCatalogFilters` →
  `/reference/filter/tire`, `getCatalogProducts` → `/catalog/tires`,
  booking → `/booking/*` (клиент, React Query).
- `getGeo()` ждут **6 серверных страниц**: каталог шин (params + auto), каталог
  дисков (params + auto), страница модели, страница типоразмера — одна 500 по
  справочнику городов роняет все шесть.
- `getCatalogFilters`/`getCatalogProducts` дополнительно роняют каталог шин
  (в т.ч. `generateMetadata` на `/catalog/tires` — метаданные ходят тем же fetch).
- `error.tsx` / `global-error.tsx` в `src/app/` нет ни одного → throw при SSR даёт
  дефолтный экран Next; статус ответа — 500.
- Обвязка (root layout) тянет `useGeo` (клиентский запрос к бэку) — страница
  ошибки **внутри layout** всё равно ходила бы в API и показывала пустой город.

## Вход / процесс / выход

- **Вход:** любое необработанное исключение (главный случай — 5xx/таймаут/
  недоступность бэка на живом эндпоинте).
- **Процесс:** `!res.ok → throw` в `shared/api/*` → исключение всплывает по
  рендеру → верхняя граница `src/app/global-error.tsx` (заменяет root layout
  целиком) → самодостаточная страница: свои `<html>/<body>`, свой импорт
  `style.css`, ни одного фетча.
- **Выход:** HTTP 500 + отрисованная страница ошибки; «Обновить» — полная
  перезагрузка; «На главную» — обычная ссылка на работающую (моковую) главную.

## Схема

```
┌─ ТРИГГЕР ─────────────────────────────────────────────────────┐
│  Заход на живую страницу:                                     │
│  прямой URL или переход по <Link> при 5xx/недоступном бэке    │
└───────────────────────────┬───────────────────────────────────┘
                            │ server render
                            ▼
┌─ ПРИЛОЖЕНИЕ (сервер) ─────────────────────────────────────────┐
│  app/catalog/tires/[[...params]]/page.tsx                     │
│  (так же: auto-каталог, каталог дисков, модель, типоразмер —  │
│   все, кто ждёт getGeo)                                       │
│       │ Promise.all                                           │
│       ├── getGeo()             → /reference/city              │
│       ├── getCatalogFilters()  → /reference/filter/tire       │
│       └── getCatalogProducts() → /catalog/tires               │
│       │ !res.ok → throw Error(`HTTP 500`)                     │
└───────┼───────────────────────────────────────────────────────┘
        │ fetch (сервер → BACKEND_URL; браузер → rewrite /api/*)
        ▼
┌─ ВНЕШНИЙ МИР ─────────────────────────────────────────────────┐
│  Laravel-бэк: 5xx / таймаут / недоступен                      │
└───────┬───────────────────────────────────────────────────────┘
        │ исключение всплывает по рендеру
        ▼
┌─ ГРАНИЦА ОШИБОК (новое) ──────────────────────────────────────┐
│  src/app/global-error.tsx — верхняя React-граница;            │
│  ЗАМЕНЯЕТ root layout целиком:                                │
│  • ни шапки/подвала/меню, ни клиентских хуков (useGeo)        │
│  • ни одного запроса к API — страница самодостаточна          │
│  • свои <html lang="ru">/<body> + импорт ./style.css          │
│  • <title> вручную (metadata-экспорт в client-компоненте нет) │
│       ├── «Что-то пошло не так» + текст                       │
│       ├── кнопка «Обновить» → window.location.reload()        │
│       └── ссылка «На главную» → <a href="/">                  │
└───────────────────────────────────────────────────────────────┘
```

## Решения (итерация 2)

1. **`global-error.tsx`, не `error.tsx`** (по требованию: страница ошибки не
   зависит от API вообще). `error.tsx` рисуется внутри root layout, а обвязка
   тянет живой `useGeo` — запрос к бэку и пустой город. `global-error` заменяет
   layout целиком → страница самодостаточна. Он же ловит ошибки самого root
   layout (на будущее), поэтому второй границы не нужно.
2. **Кнопки:** «Обновить» — `window.location.reload()` (полная перезагрузка, без
   зависимости от состояния рантайма; `unstable_retry` отклонён — помечен
   unstable и делает «мягкий» повторный рендер, что для страницы-краха лишняя
   механика). «На главную» — обычная ссылка `<a href="/">` (полная загрузка;
   главная на моках живёт при мёртвом бэке).
3. **Единое поведение без точечных смягчений**: любое необработанное исключение —
   у мок-страниц с живым `getGeo` тоже — показывает страницу ошибки. Бэк не
   отвечает → сайт нерабочий; спец-код под переходный период не пишем.
4. **Unit-тестов не заводим**: код — интеграция с фреймворк-границей; Vitest в
   проекте node-only (`tests/**/*.test.ts`), RTL не подключён. Проверка —
   прогоны с заваленным бэком (красный — текущее падение, зелёный — после).

Вне области: 404-страница (`notFound()` сейчас даёт дефолт Next), тихие пустые
состояния booking, пустой город в шапке при недоступном гео, `error.tsx` для
внутренних границ (появится, если понадобится секционный фолбэк не от бэка).

## Задачи

1. `src/app/global-error.tsx` — client component; пропсы Next 16.2:
   `{ error: Error & { digest?: string }; unstable_retry: () => void }`
   (`unstable_retry` — в сигнатуре фреймворка, не используем). Разметка:
   `<html lang="ru">` + `<body>`; логотип (статичный `/assets/img/logo.svg`),
   заголовок «Что-то пошло не так», текст «Сервис временно недоступен. Попробуйте
   обновить страницу или зайдите позже», кнопка «Обновить» (`primary-button`),
   ссылка «На главную». `<title>` через React-элемент. `import "./style.css"`.
   `console.error(error)` в `useEffect` (digest — для сверки с серверным логом).
2. `src/app/style.css` — блок `.error-page` в конец файла с пометкой 15.10.2026
   (страницы в макете нет — кастомная, как корзина/ЛК).
3. Прогоны по тест-листу, запись в «Прогоны» (красный — до `global-error.tsx`).

## Тест-лист

Unit-тестов нет (см. решение 4); контракт — сценарии прогона с заглушкой бэка,
отдающей 500 на любой запрос (BACKEND_URL контейнера → заглушка).

── Прогон: заваленный бэк ─────────────────────────────────────

Сценарий 1
1. Поведение: прямой заход на живую страницу при 500 бэка отдаёт HTTP 500 и
   нашу самодостаточную страницу ошибки вместо дефолтного экрана Next; страница
   не делает ни одного запроса к /api (ни кэш, ни хуки). Сейчас (до правки) этот
   прогон красный — фиксируем дефолтный экран Next
2. Вход: BACKEND_URL → заглушка 500; GET /catalog/tires?city=chelyabinsk (curl + браузер)
3. Ожидание: статус 500; в разметке заголовок страницы ошибки и обе кнопки;
   шапки/подвала нет; playwright-перехват: после загрузки ни одного запроса на /api
4. Имя: e2e_direct_visit_backend_500_shows_standalone_error_page

Сценарий 2
1. Поведение: после оживления бэка кнопка «Обновить» перезагружает страницу и
   вместо ошибки приходит контент
2. Вход: заглушка 500 → переключение на живой бэк → клик «Обновить» на /catalog/tires
3. Ожидание: карточки товаров отрисованы, страницы ошибки нет
4. Имя: e2e_reload_after_backend_recovery_renders_content

Сценарий 3
1. Поведение: клиентский переход по <Link> на живую страницу при мёртвом бэке
   показывает страницу ошибки (не белый экран и не дефолт Next); «На главную»
   возвращает на работающую главную
2. Вход: главная (мок, жива) → клик «Шины» в меню при заглушке 500
3. Ожидание: страница ошибки отрисована; после клика «На главную» открывается
   главная страница (полная загрузка)
4. Имя: e2e_client_nav_backend_down_shows_error_page

Сценарий 4 (страж)
1. Поведение: страницы без живых фетчей (главная, статьи, корзина) при мёртвом
   бэке открываются как обычно — граница ошибок туда не протекает
2. Вход: заглушка 500; GET /, /articles, /cart
3. Ожидание: страницы отрисованы, страницы ошибки нет
4. Имя: e2e_mock_pages_stay_alive_backend_down

Сценарий 5
1. Поведение: согласованное решение 3 — мок-страница с живым getGeo при 500
   города тоже показывает страницу ошибки (единое поведение)
2. Вход: заглушка 500; GET /tires/viatti-strada-2/185-55-r15-84h
3. Ожидание: страница ошибки
4. Имя: e2e_geo_failure_falls_back_on_mock_page

Открытые вопросы прогона — закрыты сценариями 1 и 3: `global-error` ловит и ошибки
страниц (не только root layout), и ошибку `generateMetadata` каталога (try/catch
метаданным не нужен); при клиентском переходе (свои html/body) рендерится корректно.

## Прогоны

- **Красный** (до правки; заглушка 500, dev-контейнер :30034):
  `GET /catalog/tires?city=chelyabinsk` → 500, дефолтный экран Next
  («Runtime Error: getCatalogProducts: HTTP 500»), шапки/подвала нет;
  мок-страница с живым getGeo (`/tires/viatti-strada-2/185-55-r15-84h`) → 500;
  `/`, `/articles`, `/cart` → 200.
- **Зелёный** (прод-сборка :3010, `BACKEND_URL` → переключаемая заглушка :8082;
  «live» — прокси на реальный бэк):
  - сценарий 1: `/catalog/tires` → 500, наша страница (title «Что-то пошло не так —
    Альянс», обе кнопки), запросов к /api — **0**, шапки/подвала нет;
  - сценарий 2: переключение заглушки в live, клик «Обновить» → 12 карточек товара,
    страница ошибки исчезла;
  - сценарий 3: с живой главной клик «Шины» при мёртвом бэке → страница ошибки
    (без перезагрузки), «На главную» → главная;
  - сценарий 4: `/`, `/articles`, `/cart` → 200;
  - сценарий 5: `/tires/viatti-strada-2/185-55-r15-84h` → 500 + страница ошибки.
- **Проверки**: `npm test` — 80 passed; `tsc --noEmit` — чисто; `eslint` — 0 ошибок
  (+1 намеренное отключение `no-html-link-for-pages` у ссылки «На главную»;
  15 прежних предупреждений).
- Замечание: в этой версии Next 500-ответ отдаёт оболочку `__next_error__`, а сама
  страница ошибки отрисовывается клиентом (js без изменений — как и у дефолтной
  страницы Next; без JS виден пустой документ).

## Ожидаемый результат

- 500 от бэка больше не отдаёт дефолтный экран Next: показывается наша страница
  ошибки, не зависящая от API, с кнопками «Обновить» и «На главную».
- Ошибка остаётся в логах: серверную пишет Next (pm2 logs, по `digest`),
  клиентскую логирует страница.
- ADR не требуется (стандартная механика фреймворка); в wiki — после реализации.
