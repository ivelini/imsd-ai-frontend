# Рефакторинг мокапа: чистый HTML без JS + токены + адаптив

## Цель

Привести статичный мокап (template/) к эталону для переноса в frontend (Next.js + Tailwind): чистый HTML без JavaScript, дизайн-токены через CSS-переменные, единые брейкпоинты 640/1024/1366, страницы-состояния вместо интерактива, файлы сгруппированы по доменам.

## Задачи

1. **Реструктуризация файлов** — страницы по доменам в подпапки:
   - `index.html` — главная (переименование `main.html`)
   - `catalog/` — `index.html` (базовый), `filter-params.html`, `filter-car.html`, `filter-applied.html`, `filter-mobile.html`
   - `product/`, `cart/`, `order/` — по `index.html`
   - `popups/` — состояния попапов отдельными страницами (гео-окно, каталог-меню, корзина)
   - `assets/` остаётся в корне; пути в HTML меняются на `../assets/...`

2. **CSS (вариант C)** — один общий `style.css`:
   - дизайн-токены: `--color-*`, `--gap-*`, `--bp-*` (640/1024/1366)
   - секции по компонентам, единая БЭМ-конвенция
   - вычистить дубли (`.filter-price` ×4, `.catalog-product-title` ×2), 80 `!important`, мёртвый хвост `@media all and (max-width: …)`

3. **Убрать JS со всех страниц**:
   - Slick (главная, товар) → CSS scroll-snap карусель
   - noUiSlider (фильтр цены) → статичная имитация: трек с CSS-позиционированными ползунками + числовые поля
   - инлайн-скрипты, jQuery, Slick, fancybox — удалить из разметки
   - интерактив → страницы-состояния (готовые классы в разметке)

4. **Каталог** — 5 страниц-состояний фильтра (закрыт / «По параметрам» / «По автомобилю» / применён / мобильный drawer), исправить баг разметки (два `class` в одном теге).

5. **Верификация** — каждая страница на всех разрешениях: 390/768/1024/1366/1920 (http.server + DevTools, чек-лист по страницам).

## Ожидаемый результат

- Мокап без единого `<script>`: все состояния — статичные HTML.
- Один CSS с токенами и каноническим набором брейкпоинтов.
- Все страницы адаптивны на основных разрешениях.
- База для переноса в `frontend/`: токены → Tailwind-конфиг, страницы-состояния → роуты/сцены.
