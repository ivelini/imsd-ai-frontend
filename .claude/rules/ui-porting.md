# Правила переноса вёрстки из мокапа в Next.js

## Общий подход

1. **Разметка — 1-в-1.** Классы и DOM-структура переносятся без изменений.
2. **Семантизация тегов** — только замена на семантические HTML-элементы (`div`→`button`, `a`→`form`, чекбоксы→`input`), без смены классов.
3. **Данные — синхронные моки** из `src/data/`. API (Laravel) подключится позже.
4. **Ассеты** — в `public/assets/`, пути в CSS: `../img` → `/assets/img`, `../fonts` → `/assets/fonts`.

## Стили

5. **Глобальный `style.css`** — копия `.template/assets/css/style.css` (BEM-классы, токены `:root`), импортируется в корневой layout. Изменения из `.template/` переносятся в `src/app/style.css`.
6. **Tailwind не используется.** Вся стилизация — только через `style.css` и BEM-классы; служебные обёртки — на обычном CSS.
7. **Шрифты:** Noto Sans и Nunito (woff2) через `@font-face` в style.css. Geist-шрифты из scaffold'а удалены.
8. **Дизайн-токены `:root`** в style.css — оставить как есть, дублирование в Tailwind `@theme` не требуется.
9. **Стили домена, ещё не портированного в React, живут только в `.template/assets/css/style.css`** — переносятся в `src/app/style.css` вместе с портом домена, не раньше (пример: блок booking, 12.09.2026). Отставание `src/app/style.css` от `.template` в этих границах — норма, а не рассинхронизация.

## Интерактив

10. **Состояния мокапа** (попапы, вкладки, фильтры) → React state/props, не CSS-классы-модификаторы.
11. **JS-библиотеки мокапа** (slick, fancybox, noUiSlider) в React не нужны — заменяются нативными средствами.

## Брейкпоинты

12. Макет под 3 брейкпоинта (токены `--bp-*`): **640 / 1024 / 1366 px**, мобильный брейкпоинт каталога — **648 px**.
13. Контрольные разрешения для визуальной верификации: **390 / 768 / 1024 / 1366 / 1920 px**.
