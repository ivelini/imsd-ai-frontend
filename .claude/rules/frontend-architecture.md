# Архитектурные правила frontend (Next.js + React)

1. **Структура** — код делится на `app/` (роутинг и композиция страниц), `features/` (домены), `shared/` (переиспользуемое ядро).
2. **Изоляция доменов** — домены не импортируют компоненты друг друга; разрешены импорты типов соседнего домена, а также `shared/types`, `shared/ui`, `shared/lib`.
3. **Состояние** — серверные данные через React Query (или SSR fetch), клиентское UI-состояние через Zustand, фильтры каталога и пагинация — в URL. Правило: «React Query для данных, Zustand для UI».
4. **Работа с API** — вся бизнес-логика, фильтрация, валидация и безопасность на бэкенде (REST); фронт — только UI, маршрутизация, кэширование и отправка команд.
5. **Без Server Actions** — при наличии REST API серверные экшены не используются.
6. **HTTP-клиент** — единый клиент в `shared/api/`; API-вызовы инкапсулируются в `features/*/api/`, не размазываются по компонентам.
7. **Типы** — приоритет у DTO бэкенда (поля не выдумываются); типы локальные в `features/*/types/`, переиспользуемые — в `shared/types/`; формы имеют собственные типы, не смешиваются с DTO; Zod-схемы синхронизированы с типами.
8. **Формы** — React Hook Form для состояния, Zod для клиентской валидации (UX/подсказки); финальная валидация — только на бэкенде; ошибки бэкенда парсятся единым обработчиком.
9. **Данные на клиенте** — без `useEffect` для запросов (только React Query); клиентская фильтрация и бизнес-логика на клиенте запрещены.
10. **Тестирование** — Vitest + React Testing Library.

## Текущее состояние и план перехода

11. **Данные** — синхронные моки в `src/data/`, Zustand-сторы (`src/stores/`) работают с моками напрямую. После подключения API (Laravel) — переход на React Query, прямая работа с моками из сторов убирается.
12. **HTTP-клиент** — `shared/api/` создать при подключении API. До этого API-вызовов нет.
13. **Формы** — React Hook Form + Zod установить при появлении первых форм, отправляющих данные на backend.
14. **Тесты** — Vitest + RTL добавить после стабилизации первых 2–3 фаз переноса.
15. **Структура** — строим сразу целевую: `src/app/` (роутинг и композиция страниц), `src/features/` (домены), `src/shared/` (ядро). Компоненты создаются в домене их использования (`features/<domain>/components/`), переиспользуемые — в `shared/ui/`; layout-компоненты (Header, Footer, попапы) — в `shared/layout/`. Временных директорий (`src/components/`) не создавать.
