# Архитектурные правила frontend (Next.js + React)

1. **Структура** — код делится на `app/` (роутинг и композиция страниц), `features/` (домены), `shared/` (переиспользуемое ядро).
2. **Изоляция доменов** — домены не импортируют компоненты друг друга; разрешены импорты типов соседнего домена, а также `shared/types`, `shared/ui`, `shared/lib`.
3. **Состояние** — React Query для клиентских данных (корзина, город, ЛК), Zustand только для UI-состояния (попапы, меню, UI-флаги), фильтры каталога и пагинация — в URL. Правило: «React Query для данных, Zustand для UI».
4. **Server/Client-граница** — по умолчанию Server Component. Клиентскими становятся: интерактив (формы, мутации), анимация, браузерные API. При создании новой страницы определять природу каждого компонента ДО кода. Корзина, ЛК — клиентские; каталог, автоподбор, модель, статьи, layout-структура — серверные с клиентскими островами (город, счётчик корзины, меню-бургер); главная — серверная (данные через `await` → props), клиентские острова: MainFilter (свитчер + селекты, сабмит → /catalog/tires), карусели товаров (scroll-snap).
5. **Работа с API** — вся бизнес-логика, фильтрация, валидация и безопасность на бэкенде (REST); фронт — только UI, маршрутизация, кэширование и отправка команд.
6. **Без Server Actions** — при наличии REST API серверные экшены не используются.
7. **Источник данных** — единые async-функции в `shared/api/data.ts` (сейчас: `setTimeout` + `src/data/*`). Server Components: `await getXxx()`. Client Components: хуки React Query, оборачивающие те же функции. Компоненты не импортируют `@/data/*` напрямую. При подключении API: замена `setTimeout` на `fetch` в `shared/api/data.ts` + `rewrites()` в `next.config.ts` (`/api/*` → бэк-домен, same-origin — CORS не нужен). База: `API_BASE` (NEXT_PUBLIC_API_URL ?? "/api") — уже заложена в data.ts.
8. **API-хуки** — `features/<domain>/api/` для доменов (home, cart, catalog), `shared/layout/api/` для layout-хуков (useGeo). Каждый хук = один `useQuery`/`useMutation` с зашитым queryKey и queryFn. QueryKey-формат: `['domain', 'entity', ...params]`.
9. **Корзина** — React Query + localStorage. useCart (чтение), useAddToCart/useUpdateCartItem/useRemoveFromCart (мутации с оптимистичным обновлением). `onSettled` пишет в localStorage. useCartCount — селектор из кеша. useCartStore удалён.
10. **Типы** — приоритет у DTO бэкенда (поля не выдумываются); типы локальные в `features/*/types/`, переиспользуемые — в `shared/types/`; формы имеют собственные типы, не смешиваются с DTO; Zod-схемы синхронизированы с типами.
11. **Формы** — React Hook Form для состояния, Zod для клиентской валидации (UX/подсказки); финальная валидация — только на бэкенде; ошибки бэкенда парсятся единым обработчиком.
12. **Данные на клиенте** — без `useEffect` для запросов (только React Query); клиентская фильтрация и бизнес-логика на клиенте запрещены.
13. **Тестирование** — Vitest + React Testing Library.

## Текущее состояние и план перехода

14. **Данные** — моки в `src/data/`, доступ через `shared/api/data.ts` (async-функции с `setTimeout`). После подключения API — замена `setTimeout` на `fetch`.
15. **React Query** — `@tanstack/react-query` установлен, QueryClientProvider в ClientLayout. Используется для: корзины (мутации + localStorage), города в шапке, ЛК.
16. **Формы** — React Hook Form + Zod установить при появлении первых форм, отправляющих данные на backend.
17. **Тесты** — Vitest + RTL добавить после стабилизации первых 2–3 фаз переноса.
18. **Структура** — строим сразу целевую: `src/app/` (роутинг и композиция страниц), `src/features/` (домены), `src/shared/` (ядро). Компоненты создаются в домене их использования (`features/<domain>/components/`), переиспользуемые — в `shared/ui/`; layout-компоненты (Header, Footer, попапы) — в `shared/layout/`. Временных директорий (`src/components/`) не создавать.
